[c001] type=mc domain=2 obj=2.5.a (Interpret basic operations of Rapid PVST+ Spanning Tree Protocol — Root port, root bridge (primary/secondary), and other port names)
Q: Refer to the exhibit. DC-CORE is the root bridge for VLAN 10 in the management block. AGG-1 was configured with spanning-tree vlan 10 root secondary, and MGMT-SW has default STP settings. DC-CORE loses power. Which switch becomes the root bridge for VLAN 10?
EXHIBIT:
    MGMT-SW# show spanning-tree vlan 10
    VLAN0010
      Spanning tree enabled protocol rstp
      Root ID    Priority    24586
                 Address     0001.4200.0100
                 Cost        3
                 Port        65 (Port-channel5)
                 Hello Time   2 sec  Max Age 20 sec  Forward Delay 15 sec
    
      Bridge ID  Priority    32778  (priority 32768 sys-id-ext 10)
                 Address     0001.4200.0200
                 Hello Time   2 sec  Max Age 20 sec  Forward Delay 15 sec
                 Aging Time  300 sec
    
    Interface           Role Sts Cost      Prio.Nbr Type
    ------------------- ---- --- --------- -------- --------------
    Fa0/24              Desg FWD 19        128.24   P2p
    Po5                 Root FWD 3         128.65   P2p
    
    AGG-1# show spanning-tree vlan 10 bridge
                                                       Hello  Max  Fwd
    Vlan                         Bridge ID              Time  Age  Dly  Protocol
    ---------------- --------------------------------- -----  ---  ---  --------
    VLAN0010         28682 (28672, 10) 0001.4200.0300    2    20   15  rstp
  * A. AGG-1, because its bridge priority of 28682 is lower than MGMT-SW's 32778
        why: Root election compares the whole bridge ID, priority first. root secondary set AGG-1 to 28672 (+10 sys-id-ext = 28682), which beats MGMT-SW's default 32768 + 10. The MAC address is only a tie-breaker.
    B. MGMT-SW, because its MAC address 0001.4200.0200 is lower than AGG-1's
        why: The MAC address is compared only when priorities tie. 28682 is lower than 32778, so AGG-1 wins before MAC addresses are considered.
    C. AGG-1, and it takes priority 24586 because root secondary copies the primary's value
        why: root secondary sets 28672 on the switch where it is entered. It does not copy anything from the primary, and the exhibit shows AGG-1 at 28682.
    D. No switch; VLAN 10 has no root bridge until DC-CORE comes back
        why: STP always elects a root among the switches that remain. The surviving switches stop receiving DC-CORE's BPDUs and elect the best remaining bridge ID.
TAKEAWAY: Root = lowest bridge ID: priority (multiple of 4096 + VLAN) first, MAC only on a tie. root primary sets 24576 (or lower if needed); root secondary sets 28672.

[c002] type=ms pick=2 domain=1 obj=1.2.c (Describe characteristics of network topology architectures — Spine-leaf)
Q: Refer to the exhibit. The data center team drafted the cabling plan for its new spine-leaf fabric. Which two changes are needed for the plan to follow spine-leaf design rules? (Choose two.)
EXHIBIT:
    New fabric cabling plan
    
    SPINE-1   to  LEAF-1, LEAF-2, LEAF-3, LEAF-4
    SPINE-2   to  LEAF-1, LEAF-2, LEAF-3
    SPINE-1   to  SPINE-2   (2 links, for east-west traffic)
    LEAF-1    to  hypervisor hosts, rack 1
    LEAF-2    to  hypervisor hosts, rack 2
    LEAF-3    to  storage arrays, rack 3
    LEAF-4    to  border routers and firewalls
  * A. Cable LEAF-4 to SPINE-2
        why: Every leaf connects to every spine. With LEAF-4 on SPINE-1 only, traffic from LEAF-4 has half the uplink capacity and loses the fabric if SPINE-1 fails.
  * B. Remove the links between SPINE-1 and SPINE-2
        why: Spines do not connect to each other. Any leaf reaches any other leaf through any spine, so a spine-to-spine link adds nothing but an extra, uneven path.
    C. Add a direct link between LEAF-1 and LEAF-2 for VM migration traffic
        why: Leaves do not connect to each other in spine-leaf. Rack-to-rack traffic goes leaf, spine, leaf, which keeps every path the same length.
    D. Move the storage arrays from LEAF-3 to the spines
        why: Endpoints, including storage, attach to leaves only. Spines carry nothing but leaf-to-leaf traffic.
    E. Add a core layer above the spines to aggregate them
        why: That would turn the fabric back into a three-tier design. Spine-leaf grows outward: add leaves for ports, add spines for bandwidth.
    F. Move the border routers and firewalls from LEAF-4 to SPINE-1
        why: External connections land on a leaf (a border leaf), like any other device. Attaching them to one spine breaks the uniform leaf-spine-leaf path.
TAKEAWAY: Spine-leaf: every leaf to every spine, no leaf-leaf or spine-spine links, endpoints only on leaves. Any server to any server is leaf, spine, leaf: predictable latency for east-west traffic.

[c003] type=mc domain=6 obj=6.6 (Recognize the capabilities of configuration management mechanisms such as Ansible and Terraform)
Q: Refer to the exhibit. The automation team ran a playbook that adds VLAN 150 to the four leaf switches. Which statement about the result is true?
EXHIBIT:
    $ ansible-playbook -i inventory.ini add-vlan150.yml
    
    PLAY [Add backup VLAN to leaf switches] ****************************
    
    TASK [Ensure VLAN 150 BACKUP exists] *******************************
    ok: [LEAF-1]
    changed: [LEAF-2]
    ok: [LEAF-3]
    changed: [LEAF-4]
    
    PLAY RECAP *********************************************************
    LEAF-1  : ok=1  changed=0  unreachable=0  failed=0  skipped=0
    LEAF-2  : ok=1  changed=1  unreachable=0  failed=0  skipped=0
    LEAF-3  : ok=1  changed=0  unreachable=0  failed=0  skipped=0

  * A. LEAF-1 and LEAF-3 already had VLAN 150, so nothing was changed on them; only LEAF-2 and LEAF-4 were modified
        why: Ansible modules are written to be idempotent: they compare the desired state with the device and change only what differs. ok means already compliant; changed means the module had to configure something.
    B. The task failed on LEAF-1 and LEAF-3, which reported ok instead of changed

        why: An idempotent task describes an end state. On a second run all four leaves already match it, so every host reports ok and changed=0.
TAKEAWAY: Ansible run output: ok = already in desired state, changed = modified, failed / unreachable = errors. Idempotent modules make playbooks safe to rerun. Agentless, push over SSH, YAML playbooks, inventory of hosts and groups.

[c004] type=mc domain=1 obj=1.6 (Configure and verify IPv4 addressing and subnetting)
Q: Refer to the exhibit. New VLAN 123 on LEAF-2 needs addresses for 25 servers. Its subnet must come from 10.60.21.0/24, must not overlap any existing subnet, and must be the smallest size that fits. Which SVI address configuration meets these requirements?
EXHIBIT:
    LEAF-2# show ip route connected
          10.0.0.0/8 is variably subnetted, 8 subnets, 5 masks
    C        10.60.21.0/25 is directly connected, Vlan121
    L        10.60.21.1/32 is directly connected, Vlan121
    C        10.60.21.128/27 is directly connected, Vlan122
    L        10.60.21.129/32 is directly connected, Vlan122
    C        10.60.21.192/26 is directly connected, Vlan124
    L        10.60.21.193/32 is directly connected, Vlan124
    C        10.60.255.12/30 is directly connected, TenGigabitEthernet1/1/2
    L        10.60.255.13/32 is directly connected, TenGigabitEthernet1/1/2
  * A. ip address 10.60.21.161 255.255.255.224
        why: Used space: .0-.127 (/25), .128-.159 (/27) and .192-.255 (/26). The gap .160-.191 is exactly one /27 with 30 usable addresses, enough for 25 servers, and .161 is its first host.
    B. ip address 10.60.21.161 255.255.255.192
        why: A /26 containing .161 is 10.60.21.128/26 (.128-.191), which overlaps Vlan122's 10.60.21.128/27. IOS rejects the overlapping address.
    C. ip address 10.60.21.177 255.255.255.240
        why: 10.60.21.176/28 is free, but a /28 has only 14 usable addresses, too few for 25 servers.
    D. ip address 10.60.21.97 255.255.255.224
        why: 10.60.21.96/27 falls inside Vlan121's 10.60.21.0/25 (.0-.127), so it overlaps.
TAKEAWAY: Find free space: list each subnet's range (network to broadcast), look for a gap on a block boundary, and pick the smallest mask with 2^h - 2 >= hosts. 25 hosts needs h = 5: /27, 30 usable.

[c005] type=mc domain=2 obj=2.4 (Configure and verify (Layer 2/Layer 3) EtherChannel (LACP))
Q: Refer to the exhibit. DC-CORE and MGMT-SW are joined by an LACP bundle, Po5. MGMT-SW's members are in passive mode. What is the current state of the bundle?
EXHIBIT:
    DC-CORE# show etherchannel summary
    Flags:  D - down        P - bundled in port-channel
            I - stand-alone s - suspended
            H - Hot-standby (LACP only)
            R - Layer3      S - Layer2
            U - in use
    
    Number of channel-groups in use: 1
    Number of aggregators:           1
    
    Group  Port-channel  Protocol    Ports
    ------+-------------+-----------+------------------------------------------
    5      Po5(SU)       LACP        Gi1/0/21(P) Gi1/0/22(s)
    
    DC-CORE# show running-config interface gigabitEthernet1/0/21
    interface GigabitEthernet1/0/21
     switchport trunk allowed vlan 10,20,140
     switchport mode trunk
     channel-group 5 mode active
    
    DC-CORE# show running-config interface gigabitEthernet1/0/22
    interface GigabitEthernet1/0/22
     switchport trunk allowed vlan 10,20
     switchport mode trunk
     channel-group 5 mode active
  * A. Gi1/0/22 is suspended because its allowed VLAN list does not match, so Po5 carries traffic on Gi1/0/21 only
        why: Members must have matching Layer 2 settings. Gi1/0/22's allowed list differs, so IOS suspends it (s) and Po5 stays up (SU) with one bundled port (P). Making the lists match lets it bundle.
    B. Gi1/0/22 is a hot-standby LACP member that will bundle only if Gi1/0/21 fails
        why: Hot-standby is flag H, used when more ports are configured than the bundle allows. The flag shown is s, suspended.
    C. The bundle cannot form because active on DC-CORE and passive on MGMT-SW are incompatible
        why: Active with passive is a valid LACP pair: the active side starts negotiation. Po5 is in use and Gi1/0/21 is bundled, which proves negotiation worked.
    D. Gi1/0/22 is stand-alone because MGMT-SW runs PAgP on that port
        why: A port that cannot negotiate the protocol shows I (stand-alone). The flag here is s, and the cause is visible in the differing configuration.
TAKEAWAY: etherchannel summary flags: P bundled, I stand-alone, s suspended, H hot-standby, D down; S/R Layer 2/3, U in use. Members need the same speed, duplex, mode, access/native VLAN and allowed list.

[c006] type=mc domain=1 obj=1.8 (Configure and verify IPv6 addressing and prefix)
Q: The IPv6 gateway for the backup-server segment is documented in full as 2001:0db8:0060:0000:0000:0a00:0000:0010. Which entry is the correct fully compressed form for the address plan?
  * A. 2001:db8:60::a00:0:10
        why: Leading zeros drop in each hextet (0db8 to db8, 0060 to 60, 0a00 to a00, 0010 to 10). The longest run of all-zero hextets (positions 4-5) becomes ::, and the lone zero hextet stays 0.
    B. 2001:db8:60::a00::10
        why: Only one :: is allowed in an address. With two, a reader cannot tell how many zero hextets each one replaces.
    C. 2001:db8:60::a:0:10
        why: Only leading zeros can be removed. Trimming the trailing zeros of a00 changes the value to 000a.
    D. 2001:db8:60:0:0:a00::10
        why: This expands to the same address, but it is not fully compressed: :: should replace the longest zero run (two hextets), not a single zero hextet.
TAKEAWAY: IPv6 compression: drop leading zeros in each hextet; replace the longest run of zero hextets with :: once (leftmost if tied); never use :: for a single hextet in canonical form.

[c007] type=mc domain=2 obj=2.8 (Describe network device management access (Telnet, SSH, HTTP, HTTPS, console, TACACS+/RADIUS, and cloud managed))
Q: Refer to the exhibit. The TACACS+ server at 10.60.250.20 is powered off for maintenance. An engineer opens an SSH session to LEAF-3 with the local account netops, which exists on LEAF-3. What happens?
EXHIBIT:
    LEAF-3# show running-config
    ...
    aaa new-model
    aaa authentication login VTY-LOGIN group tacacs+ local
    !
    tacacs server TAC-1
     address ipv4 10.60.250.20
     key 7 08154D4D5D1A165A36285A54
    !
    line vty 0 15
     login authentication VTY-LOGIN
     transport input ssh
    ...
  * A. LEAF-3 gets no answer from the TACACS+ server, then checks its local user database, and netops logs in
        why: A method list moves to the next method only when the current one returns an error, such as an unreachable server. The local method then authenticates netops.
    B. The login fails, because local is used only when the TACACS+ server rejects the credentials
        why: It is the other way round. A reject from the server is final; local is tried only when the server cannot be reached.
    C. LEAF-3 falls back to the password configured under the vty lines
        why: The vty lines use the VTY-LOGIN list, so only its methods apply: TACACS+ and then local. A line password is not one of them.
    D. LEAF-3 forwards the login to a RADIUS server as the standard backup for TACACS+
        why: Only the methods named in the list are used. No RADIUS group is configured or listed.
TAKEAWAY: AAA method lists fail over only on an error (no response). An explicit reject ends the attempt. Keep a local account as the last method so devices stay reachable when the AAA server is down.

[c009] type=order domain=6 obj=6.5 (Describe characteristics of REST-based APIs (authentication types, CRUD, HTTP verbs, and data encoding))
Q: A test script exercises the fabric controller's VLAN API: it creates VLAN 150, reads it back, renames it, deletes it, and finally confirms that it is gone. Drag the requests and responses into the order in which they occur.
POOL:
  [0] PATCH /api/v1/vlans/150 with {"name": "BACKUP-NET"}, then 200 OK
  [1] GET /api/v1/vlans/150, then 404 Not Found
  [2] POST /api/v1/vlans with {"vlanId": 150, "name": "BACKUP"}, then 201 Created
  [3] DELETE /api/v1/vlans/150, then 204 No Content
  [4] GET /api/v1/vlans/150, then 200 OK with the VLAN's JSON
KEY (full order): [2] -> [4] -> [0] -> [3] -> [1]
why: CRUD maps to HTTP verbs: create with POST to the collection (201 Created), read with GET (200 OK with a body), update part of a resource with PATCH, and delete with DELETE (often 204 No Content, a success with no body). A GET for a resource that no longer exists returns 404 Not Found, which confirms the delete.
TAKEAWAY: CRUD to HTTP: Create POST (201), Read GET (200), Update PUT (replace) or PATCH (modify part), Delete DELETE (200/204). 404 = no such resource; 401 = not authenticated; 403 = authenticated but not allowed.

[c010] type=mc domain=2 obj=2.1.a (Configure and verify VLANs (normal range) spanning multiple switches — Access ports (data and voice))
Q: Refer to the exhibit. A database server on LEAF-2 Gi1/0/12 belongs in VLAN 130. Its link LED is green, but it cannot reach its gateway or any host in VLAN 130. VLAN 130 was removed from LEAF-2 during a cleanup last week. Which action restores connectivity?

[c011] type=build ordered=false domain=1 obj=1.12 (Explain virtualization fundamentals (server virtualization, containers, and VRFs))
Q: The platform team is moving several web services from virtual machines to containers. Drag the characteristics of containers, compared with virtual machines, into the answer area. Leave the characteristics that do not apply.
POOL:
  [0] Share the host operating system's kernel
  [1] Start in seconds or less because no guest operating system boots
  [2] Package an application with its libraries and dependencies
  [3] Each instance runs its own complete guest operating system
  [4] A hypervisor emulates virtual hardware for each instance
  [5] Can run a different kernel family from the host, such as Windows on a Linux host
  [6] Usually need less memory and disk than an equivalent virtual machine
KEY (unordered subset): [0] + [1] + [2] + [6]
why: A container is an isolated process group on a shared host kernel, packaged with its own libraries and dependencies. With no guest OS to boot, it starts quickly and uses fewer resources. A full guest OS per instance and virtual hardware emulated by a hypervisor describe VMs, and because containers share the kernel they cannot natively run a different kernel family.
TAKEAWAY: VM: hypervisor (type 1 bare-metal or type 2 hosted), virtual hardware, a full guest OS each. Container: shared host kernel, app + dependencies, lightweight, fast start; orchestrated with tools such as Kubernetes.

[c012] type=mc domain=2 obj=2.6 (Describe Cisco Wireless Architectures and AP modes)
Q: The new operations building gets 12 APs. The team wants no controller hardware on site or in the data center: the APs are configured and monitored from a vendor-hosted web dashboard, and they switch client traffic onto the local LAN. Which wireless architecture fits?
  * A. Cloud-based architecture with cloud-managed APs
        why: Cloud-managed APs take their configuration and send monitoring data to a controller hosted in the cloud. Only management traffic goes there; client traffic is switched locally.
    B. Autonomous APs
        why: Autonomous APs need no controller, but each one is configured and monitored on its own. There is no central dashboard.
    C. Centralized (split-MAC) architecture with lightweight APs in local mode
        why: Lightweight APs in local mode need a WLC, and they tunnel all client traffic to it in CAPWAP rather than switching it locally.
    D. Lightweight APs in FlexConnect mode
        why: FlexConnect switches traffic locally, but the APs still need a WLC to join, which the team wants to avoid.
TAKEAWAY: Wireless architectures: autonomous (standalone, managed one by one), centralized/split-MAC (lightweight APs + WLC, CAPWAP), FlexConnect (remote APs, central WLC, local switching), cloud-based (cloud dashboard, local switching).

[c013] type=ms pick=3 domain=1 obj=1.9 (Describe IPv6 address types)
Q: Refer to the exhibit. LEAF-2's VLAN 110 SVI has MAC address 00a7.42d1.3c40 and is the gateway for the web-server segment. Which three statements about the output are true? (Choose three.)
EXHIBIT:
    LEAF-2# show ipv6 interface vlan 110
    Vlan110 is up, line protocol is up
      IPv6 is enabled, link-local address is FE80::2A7:42FF:FED1:3C40
      No Virtual link-local address(es):
      Global unicast address(es):
        2001:DB8:60:110::1, subnet is 2001:DB8:60:110::/64
      Joined group address(es):
        FF02::1
        FF02::2
        FF02::1:FF00:1
        FF02::1:FFD1:3C40
      MTU is 1500 bytes
      ICMP error messages limited to one every 100 milliseconds
      ICMP redirects are enabled
      ICMP unreachables are sent
      ND DAD is enabled, number of DAD attempts: 1
      ND reachable time is 30000 milliseconds (using 30000)
      ND advertised reachable time is 0 (unspecified)
      ND advertised retransmit interval is 0 (unspecified)
      ND router advertisements are sent every 200 seconds
      ND router advertisements live for 1800 seconds
      ND advertised default router preference is Medium
      Hosts use stateless autoconfig for addresses.
  * A. The link-local address was built from the SVI's MAC address with modified EUI-64
        why: The interface ID 02A7:42FF:FED1:3C40 is the MAC split in half with FFFE inserted, and 00 became 02 because the seventh bit was inverted.
  * B. FF02::1:FF00:1 is the solicited-node group that neighbors use to resolve 2001:db8:60:110::1
        why: A solicited-node group is FF02::1:FF plus the last 24 bits of a unicast address. The GUA ends in 00:0001, so its group is FF02::1:FF00:1, used for neighbor solicitations and DAD.
  * C. Membership in FF02::2 shows that LEAF-2 is acting as an IPv6 router
        why: FF02::2 is the all-routers group. IOS joins it, and sends router advertisements, once ipv6 unicast-routing is enabled.
    D. The global unicast address was also generated with EUI-64
        why: The interface ID of the GUA is ::1, not a MAC-derived value with FFFE in the middle, so it was configured statically.
    E. Hosts in other subnets can use the link-local address to reach LEAF-2
        why: Link-local (FE80::/10) addresses are valid only on the local link. Routers never forward packets sourced from or sent to them.
    F. FF02::1 is an anycast address that only the nearest router answers
        why: FF02::1 is the link-scope all-nodes multicast group. Every IPv6 interface on the link joins it.
TAKEAWAY: IPv6 interface groups: FF02::1 all nodes, FF02::2 all routers (routing on), FF02::1:FFxx:xxxx solicited-node per unicast/anycast address (last 24 bits). FFFE in the middle of an interface ID = EUI-64.

[c014] type=mc domain=2 obj=2.2.a (Configure and verify interswitch connectivity — Trunk ports)
Q: Refer to the exhibit. During the migration, LEAF-1 Gi1/0/48 trunks to the legacy aggregation switch AGG-1. An engineer must also carry new VLAN 140 on this trunk and enters the commands shown. What is the result?
EXHIBIT:
    LEAF-1# show interfaces trunk
    
    Port        Mode             Encapsulation  Status        Native vlan
    Gi1/0/48    on               802.1q         trunking      999
    
    Port        Vlans allowed on trunk
    Gi1/0/48    110,120,130,999
    
    Port        Vlans allowed and active in management domain
    Gi1/0/48    110,120,130,999
    
    Port        Vlans in spanning tree forwarding state and not pruned
    Gi1/0/48    110,120,130,999
    
    LEAF-1# configure terminal
    LEAF-1(config)# interface gigabitEthernet1/0/48
    LEAF-1(config-if)# switchport trunk allowed vlan 140
  * A. VLAN 140 becomes the only allowed VLAN, so VLANs 110, 120, 130 and native VLAN 999 stop crossing the trunk
        why: switchport trunk allowed vlan with a plain list replaces the existing list. Only the add keyword appends. The native VLAN is dropped too, because it is no longer in the allowed list.
    B. VLAN 140 is added to the existing allowed list
        why: Adding needs switchport trunk allowed vlan add 140. Without add, the command overwrites the list.
    C. The command is rejected because VLAN 140 has not been created on LEAF-1

    C. [110/3] through both SPINE-1 and SPINE-2
        why: 3 would be the spine path cost with the old 100-Mb/s reference, where every link costs 1. The new reference changes every interface cost.
    D. [110/120] through SPINE-1, with SPINE-2 held as a backup
        why: Both spine paths total exactly 120, so OSPF installs both and load-shares. OSPF does not keep an equal-cost path as a standby.
TAKEAWAY: Cost = reference bandwidth / interface bandwidth. At 100000 Mb/s: 100G = 1, 10G = 10, 1G = 100. Set the same reference on every router, or path costs become inconsistent.

[c095] type=mc domain=4 obj=4.8 (Configure network devices for remote access using SSH)
Q: Refer to the exhibit. An audit requires DC-EDGE to refuse SSH version 1 sessions. DC-EDGE already has a 2048-bit RSA key. Which command meets the requirement?
EXHIBIT:
    DC-EDGE# show ip ssh
    SSH Enabled - version 1.99
    Authentication methods:publickey,keyboard-interactive,password
    Authentication timeout: 120 secs; Authentication retries: 3
    Minimum expected Diffie Hellman key size : 1024 bits
    IOS Keys in SECSH format(ssh-rsa, base64 encoded): DC-EDGE.dc.example
  * A. ip ssh version 2
        why: Version 1.99 means the server accepts both SSHv1 and SSHv2 clients. Setting version 2 makes DC-EDGE refuse SSHv1.
    B. crypto key generate rsa modulus 4096
        why: A larger key strengthens the host key but does not change which protocol versions are accepted. The 2048-bit key already supports SSHv2.
    C. transport input ssh under line vty 0 15
        why: transport input chooses between protocols such as SSH and Telnet. It does not select the SSH version.
    D. ip ssh authentication-retries 2
        why: This only limits failed login attempts per session. Version 1 clients would still be accepted.
TAKEAWAY: SSH on IOS: hostname, ip domain-name, crypto key generate rsa (768+ bits for v2), ip ssh version 2, login local, transport input ssh. 1.99 = v1 and v2 both allowed.

[c096] type=mc domain=5 obj=5.10 (Configure and verify WLAN within the GUI using WPA2 PSK)
Q: Refer to the exhibit. The OPS-LAB WLAN on the controller must use WPA2-Personal with the AES-based encryption (CCMP) that WPA2 is built around. A wireless audit flagged the WLAN as non-compliant. Which change fixes it?
EXHIBIT:
    WLANs > Edit 'OPS-LAB'   Security > Layer 2
    
      Layer 2 Security          WPA+WPA2
      WPA+WPA2 Parameters
        WPA Policy              [ ]
        WPA2 Policy             [x]
        WPA2 Encryption         [ ] AES    [x] TKIP
      Authentication Key Management
        802.1X                  [ ] Enable
        PSK                     [x] Enable
        PSK Format              ASCII
  * A. Check AES and clear TKIP under WPA2 Encryption
        why: WPA2 is defined around AES-CCMP. TKIP is a legacy cipher from WPA that is deprecated and weaker. WPA2 policy, PSK key management and an ASCII passphrase are already set correctly.
    B. Enable 802.1X and keep PSK enabled
        why: 802.1X is enterprise key management with a RADIUS server. The requirement is WPA2-Personal, which is PSK.
    C. Enable WPA Policy alongside WPA2 Policy
        why: That adds the original WPA with TKIP for older clients, which moves the WLAN further from the requirement.
    D. Change the PSK Format from ASCII to HEX
        why: The format only defines how the key is entered (an 8 to 63 character passphrase or 64 hex digits). It does not affect the cipher.
TAKEAWAY: WLC WPA2-Personal: Layer 2 Security WPA+WPA2, WPA2 Policy on, encryption AES, Auth Key Mgmt PSK, then the passphrase. TKIP belongs to the original WPA.

[c097] type=mc domain=3 obj=3.3.a (Configure and verify IPv4 and IPv6 static routing — Default route)
Q: Refer to the exhibit. IPv6 unicast routing is enabled on DC-EDGE. The ISP router on the Gi0/0 link uses 2001:DB8:A0:1::1. Which command gives DC-EDGE a default route for every IPv6 destination it has no more specific route for?
EXHIBIT:
    DC-EDGE# show ipv6 interface brief
    GigabitEthernet0/0     [up/up]
        FE80::A8BB:CCFF:FE00:200
        2001:DB8:A0:1::2
    GigabitEthernet0/1     [up/up]
        FE80::A8BB:CCFF:FE00:210
        2001:DB8:60:FFFF::1
  * A. ipv6 route ::/0 2001:db8:a0:1::1
        why: ::/0 is the IPv6 default route; a zero-length prefix matches every address. The ISP's global address is on the connected Gi0/0 prefix, so the next hop resolves.
    B. ipv6 route ::/128 2001:db8:a0:1::1
        why: ::/128 is a host route for the unspecified address only. It would match nothing useful.
    C. ipv6 route ::/0 FE80::1
        why: A link-local next hop must be paired with an exit interface, and FE80::1 is not shown as the ISP's address anyway.
    D. ip route 0.0.0.0 0.0.0.0 2001:db8:a0:1::1
        why: ip route builds IPv4 routes and cannot take an IPv6 next hop. IPv6 routes use ipv6 route.
TAKEAWAY: IPv6 default route: ipv6 route ::/0 <next hop>. Use a global next hop, or an exit interface plus a link-local next hop. ipv6 unicast-routing must be on.

[c098] type=mc domain=5 obj=5.4 (Describe security password policy elements, such as management, complexity, and password alternatives (multifactor authentication, certificates, and biometrics))
Q: A new policy requires every password configured on the data center devices to have at least 12 characters. After a change on DC-CORE, IOS rejects the command username ops2 secret Dc!2026 with a password-length error. Which command enforces this policy?
  * A. security passwords min-length 12
        why: This global command makes IOS refuse new user, enable and line passwords shorter than the configured length, which is what the error shows.
    B. service password-encryption
        why: This only obscures clear-text passwords in the configuration with weak type 7 encoding. It enforces no length.
    C. login block-for 120 attempts 5 within 60
        why: This blocks logins for 120 seconds after 5 failures in 60 seconds. It slows password guessing but does not check how passwords are set.
    D. exec-timeout 12 0 under line vty 0 15
        why: This logs idle vty sessions out after 12 minutes. It has nothing to do with password length.
TAKEAWAY: Password policy on IOS: security passwords min-length (length), enable secret / username secret (strong hashing), login block-for (guessing), exec-timeout (idle sessions). Better still: MFA or certificates.

[c099] type=mc domain=4 obj=4.9 (Describe the capabilities and functions of TFTP/FTP in the network)
Q: DC-CORE copies a new 480-MB software image from the file server 10.60.20.60 with copy ftp: flash:. A transit ACL between them permits only TCP port 21 in each direction. The FTP login succeeds, but the transfer fails before any of the file arrives. What is the reason?
  * A. FTP carries the file over a separate TCP data connection, which the ACL does not permit
        why: TCP 21 is only the control connection used for login and commands. The file itself moves over a second TCP connection (port 20 in active mode, a negotiated port in passive mode), which this ACL blocks.
    B. FTP sends files over UDP port 69, which the ACL does not permit
        why: UDP 69 is TFTP. FTP runs entirely over TCP.
    C. FTP cannot transfer files larger than 32 MB
        why: That ceiling belongs to classic TFTP (512-byte blocks and a 16-bit block counter). FTP has no such limit.
    D. The username and password must be sent again on TCP port 20 before the transfer starts
        why: Credentials are exchanged once, on the control connection. The data connection carries only file contents.
TAKEAWAY: FTP: TCP, login with credentials, control on 21 plus a separate data connection. TFTP: UDP 69, no login, simple and slow. Both copy images and configs to and from IOS.

[c100] type=mc domain=5 obj=5.8 (Compare authentication, authorization, and accounting concepts)
Q: The ops team must choose a protocol for administrator logins to the data center switches and routers. Requirements: each configuration command must be authorized individually, and the entire packet body, not just the password, must be encrypted. Which choice meets the requirements, and why?
  * A. TACACS+, because it separates authorization from authentication and encrypts the whole payload over TCP 49
        why: TACACS+ handles authentication, authorization and accounting as separate exchanges, which allows per-command authorization, and it encrypts the full body of every packet.
    B. RADIUS, because it encrypts the whole payload over UDP 1812
        why: RADIUS uses UDP 1812/1813 but encrypts only the password attribute. The rest of the packet is sent in clear text.
    C. RADIUS, because it is the only one of the two that supports command authorization
        why: RADIUS returns authorization together with authentication and has no per-command exchange. Per-command authorization is a TACACS+ strength.
    D. TACACS+, because it combines authentication and authorization in one reply over UDP 49
        why: TACACS+ runs over TCP, not UDP, and it separates the AAA functions. Combining authentication and authorization is how RADIUS works.
TAKEAWAY: TACACS+: TCP 49, full-body encryption, separate AAA, per-command authorization: best for device administration. RADIUS: UDP 1812/1813, password-only encryption, combined authN/authZ: best for network access (802.1X, VPN).
