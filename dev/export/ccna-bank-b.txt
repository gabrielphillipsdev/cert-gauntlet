[b001] type=mc domain=2 obj=2.1.a (Configure and verify VLANs (normal range) spanning multiple switches — Access ports (data and voice))
Q: Refer to the exhibit. An IP phone is cabled to BSW1 Fa0/7 and a staff PC is cabled to the phone's PC port. The phone keeps leasing an address from the VLAN 10 staff scope instead of the 10.20.20.0/24 voice scope. VLAN 20 (VOICE) exists on BSW1 and is allowed on the uplink trunk. Which command on Fa0/7 fixes the problem and keeps the PC in VLAN 10?
EXHIBIT:
    BSW1# show interfaces fa0/7 switchport
    Name: Fa0/7
    Switchport: Enabled
    Administrative Mode: static access
    Operational Mode: static access
    Administrative Trunking Encapsulation: dot1q
    Operational Trunking Encapsulation: native
    Negotiation of Trunking: Off
    Access Mode VLAN: 10 (STAFF)
    Trunking Native Mode VLAN: 1 (default)
    Administrative Native VLAN tagging: enabled
    Voice VLAN: none
  * A. switchport voice vlan 20
        why: Voice VLAN: none means the switch never tells the phone (through CDP or LLDP-MED) to tag its traffic, so the phone sends untagged frames into access VLAN 10. With voice VLAN 20 set, the phone tags voice in VLAN 20 and the PC stays untagged in VLAN 10.
    B. switchport access vlan 20
        why: This moves all untagged traffic, and the PC with it, into VLAN 20. The phone would get a voice address but the PC would land in the voice subnet.
    C. switchport mode trunk
        why: Trunking does not tell the phone which VLAN to use for voice. With no voice VLAN advertised the phone still sends untagged frames, which a trunk places in its native VLAN.
    D. switchport trunk native vlan 20
        why: The native VLAN only matters when the port is trunking. Fa0/7 is a static access port, so this changes nothing for the phone.
TAKEAWAY: Phone port: switchport mode access, switchport access vlan <data>, switchport voice vlan <voice>. The switch advertises the voice VLAN in CDP/LLDP-MED; the phone tags voice and passes the PC's frames untagged.

[b002] type=mc domain=1 obj=1.6 (Configure and verify IPv4 addressing and subnetting)
Q: The branch warehouse is getting a scanner VLAN on BR1 subinterface Gi0/0.60. It must hold 300 handheld scanners, the address plan assigns the block starting at 10.20.64.0, the gateway must use the first usable address, and the subnet must leave the fewest unused addresses. Which interface command meets the requirements?
  * A. ip address 10.20.64.1 255.255.254.0
        why: 300 hosts need 9 host bits (2^9 - 2 = 510), so the mask is /23. 10.20.64.0/23 runs from 10.20.64.0 to 10.20.65.255, and the first usable address is 10.20.64.1.
    B. ip address 10.20.64.1 255.255.255.0
        why: A /24 gives only 254 usable addresses, fewer than the 300 scanners.
    C. ip address 10.20.64.1 255.255.252.0
        why: A /22 (1022 usable) fits, but it leaves more than 700 addresses unused. A /23 meets the need with far less waste.
    D. ip address 10.20.65.1 255.255.254.0
        why: 10.20.65.1 is inside 10.20.64.0/23, but it is not the first usable address. That is 10.20.64.1.
TAKEAWAY: Find the smallest n where 2^n - 2 covers the hosts (300 → n = 9 → /23). Check the boundary: a /23 starts on an even third octet (64 is). First usable = network + 1; broadcast = next network - 1.

[b003] type=mc domain=6 obj=6.6 (Recognize the capabilities of configuration management mechanisms such as Ansible and Terraform)
Q: Refer to the exhibit. The network team runs this file to update all branch routers. Which statement describes how it works?
EXHIBIT:
    ---
    - name: Branch NTP baseline
      hosts: branch_routers
      gather_facts: no
      connection: ansible.netcommon.network_cli
    
      tasks:
        - name: Point routers at the HQ NTP server
          cisco.ios.ios_config:
            lines:
              - ntp server 10.10.1.123
    
        - name: Save the configuration if it changed
          cisco.ios.ios_config:
            save_when: modified
  * A. A control node pushes the lines over SSH to each router in the inventory group branch_routers; no agent is installed
        why: This is an Ansible playbook in YAML. The control node connects with network_cli (SSH to the IOS CLI), runs each task in order against every host in the group, and nothing has to be installed on the routers.
    B. Each router runs an agent that periodically pulls this manifest from a central server
        why: That pull model describes Puppet and Chef. Ansible is agentless and pushes changes when someone runs the playbook.
    C. It is a Terraform configuration written in HCL, and the apply step records the routers in a state file
        why: The file is YAML with hosts and tasks, which is Ansible's playbook format. Terraform files are HCL resource blocks with a state file and plan/apply.
    D. The routers must expose a REST API, because this tool cannot manage devices through the CLI
        why: network_cli drives the device CLI over SSH. Ansible can also use NETCONF or REST modules, but this playbook does not need them.
TAKEAWAY: Ansible: agentless, push, SSH or APIs, YAML playbooks of tasks run against inventory groups, modules such as cisco.ios.ios_config. Puppet/Chef: agent-based pull. Terraform: declarative HCL, plan/apply, state file.

[b004] type=mc domain=1 obj=1.4 (Identify interface and cable issues (collisions, errors, mismatch duplex, and/or speed))
Q: Refer to the exhibit. Users at the desk on BSW1 Fa0/12 complain about slow file transfers. The PC's NIC reports an auto-negotiated 100 Mb/s full-duplex link, and the error counters keep rising after clear counters. What is the most likely cause?
EXHIBIT:
    BSW1# show interfaces fa0/12
    FastEthernet0/12 is up, line protocol is up (connected)
      Hardware is Fast Ethernet, address is 0001.4200.020c (bia 0001.4200.020c)
      MTU 1500 bytes, BW 100000 Kbit/sec, DLY 100 usec,
         reliability 238/255, txload 1/255, rxload 3/255
      Encapsulation ARPA, loopback not set
      Keepalive set (10 sec)
      Full-duplex, 100Mb/s, media type is 10/100BaseTX
      5 minute input rate 412000 bits/sec, 61 packets/sec
      5 minute output rate 389000 bits/sec, 58 packets/sec
         1840212 packets input, 1288140211 bytes, 0 no buffer
         Received 2214 broadcasts (1876 multicasts)
         0 runts, 0 giants, 0 throttles
         4127 input errors, 4127 CRC, 0 frame, 0 overrun, 0 ignored
         1702334 packets output, 1190455721 bytes, 0 underruns
         0 output errors, 0 collisions, 1 interface resets
         0 babbles, 0 late collision, 0 deferred
  * A. Damaged cabling or electrical interference between the PC and the switch
        why: CRC errors mean frames arrived with a bad frame check sequence. Both ends agree on full duplex, and there are no runts, collisions or buffer drops, which points at the physical path: a crushed cable, a bad patch cord or interference.
    B. A duplex mismatch between the switch port and the PC
        why: Both sides negotiated full duplex. A mismatch would show late collisions on the half-duplex side and usually runts on the full-duplex side, and neither appears.
    C. A speed mismatch between the switch port and the PC
        why: With mismatched speeds the link does not come up at all. The port is up/up at 100 Mb/s, the same as the NIC.
    D. The switch is overloaded and dropping frames it has no buffer space for
        why: Buffer shortage shows up as no buffer, overrun or ignored counts, which are all zero. The load is under 0.5 Mb/s on a 100 Mb/s port.
TAKEAWAY: CRC errors with no collisions on a full-duplex link = physical layer (cable, connector, EMI, NIC). CRC/runts on one end plus late collisions on the other = duplex mismatch. Speed mismatch = link down.

[b005] type=mc domain=2 obj=2.5.b (Interpret basic operations of Rapid PVST+ Spanning Tree Protocol — Port states and roles)
Q: Refer to the exhibit. BSW1 is the root bridge for VLAN 10 and connects to BSW2 Gi0/1 and BSW3 Gi0/1. BSW2 Gi0/2 connects to BSW3 Gi0/2. All links are 1 Gb/s. Which statement describes BSW3 Gi0/2?
EXHIBIT:
    BSW3# show spanning-tree vlan 10
    VLAN0010
      Spanning tree enabled protocol rstp
      Root ID    Priority    24586
                 Address     0001.4200.0100
                 Cost        4
                 Port        25 (GigabitEthernet0/1)
                 Hello Time   2 sec  Max Age 20 sec  Forward Delay 15 sec
    
      Bridge ID  Priority    32778  (priority 32768 sys-id-ext 10)
                 Address     0001.4200.0300
                 Hello Time   2 sec  Max Age 20 sec  Forward Delay 15 sec
                 Aging Time  300 sec
    
    Interface           Role Sts Cost      Prio.Nbr Type
    ------------------- ---- --- --------- -------- -----------------------
    Gi0/1               Root FWD 4         128.25   P2p
    Gi0/2               Altn BLK 4         128.26   P2p
  * A. It is an alternate port that discards frames and can become the root port immediately if Gi0/1 fails
        why: Gi0/2 offers a path to the root through BSW2 (cost 8), worse than Gi0/1's direct path (cost 4). RSTP makes it an alternate port, kept discarding (shown as BLK), ready to take over as root port at once.
    B. It is a backup port because BSW3 has two paths to the root bridge
        why: A backup port is a second port onto a segment where the same switch already has the designated port, as through a hub. Gi0/2 hears a better BPDU from another switch, so it is alternate.
    C. It is in the listening state and will forward after two forward-delay intervals
        why: Listening exists only in legacy 802.1D. Rapid PVST+ uses discarding, learning and forwarding, and an alternate port is promoted without waiting on timers.
    D. It is the designated port for the BSW2-BSW3 link because BSW3 has the higher bridge ID
        why: Both switches advertise root path cost 4 onto that link, so the lower bridge ID wins. Gi0/2 being Altn shows BSW2 sent the superior BPDU, so BSW2 has the lower bridge ID and owns the designated port.
TAKEAWAY: RSTP roles: root, designated, alternate (a backup path to the root through another switch), backup (a redundant port onto a segment this switch already serves). States: discarding, learning, forwarding.

[b006] type=mc domain=1 obj=1.10 (Verify IP parameters for Client OS (Windows, Mac OS, Linux))
Q: Refer to the exhibit. A user typed a static IPv4 configuration on this Mac in VLAN 10 (10.20.10.0/24). It reaches the internet and HQ servers, but not the branch camera server 10.20.30.15, which other staff PCs reach without problems. Proxy ARP is disabled on BR1's LAN interfaces. What explains the problem?
EXHIBIT:
    mac$ ifconfig en0
    en0: flags=8863<UP,BROADCAST,SMART,RUNNING,SIMPLEX,MULTICAST> mtu 1500
            ether 3c:22:fb:5e:10:21
            inet6 fe80::1c4d:2a9:5e11:8f02%en0 prefixlen 64 secured scopeid 0x6
            inet 10.20.10.88 netmask 0xffff0000 broadcast 10.20.255.255
            status: active
    mac$ netstat -rn -f inet
    Routing tables
    
    Internet:
    Destination        Gateway            Flags        Netif Expire
    default            10.20.10.1         UGScg          en0
    10.20/16           link#6             UCS            en0
  * A. The 0xffff0000 (/16) mask makes the Mac treat 10.20.30.15 as on-link, so it ARPs for it instead of using 10.20.10.1
        why: With /16, every 10.20.x.x address looks local, so the Mac ARPs for 10.20.30.15 on VLAN 10. The server is in another VLAN and never answers, and with proxy ARP off BR1 does not answer for it either. The mask should be 0xffffff00.
    B. The default gateway 10.20.10.1 is wrong for this subnet
        why: 10.20.10.1 is BR1's VLAN 10 gateway, and internet and HQ traffic reaches it. The gateway is right; it simply isn't used for 10.20.x.x destinations.
    C. BR1 has no route to the 10.20.30.0/24 camera subnet
        why: Other staff PCs reach the camera server through BR1, so BR1 can route to that subnet.
    D. The 10.20.255.255 broadcast lets the Mac's ARP requests reach every branch VLAN
        why: Switches keep a broadcast inside its VLAN and routers do not forward it. That is exactly why the ARP for 10.20.30.15 goes unanswered.
TAKEAWAY: Client checks: Windows ipconfig /all; macOS ifconfig and netstat -rn; Linux ip addr and ip route. A mask that is too short makes remote hosts look local (ARP, no gateway); too long makes local hosts look remote.

[b007] type=build ordered=true domain=2 obj=2.1.c (Configure and verify VLANs (normal range) spanning multiple switches — InterVLAN connectivity)
Q: Cameras will use VLAN 30 (10.20.30.0/24). BSW1 already carries VLAN 30, tagged, on its trunk to BR1 Gi0/0, which is up. Starting in global configuration mode on BR1, drag the commands needed to route VLAN 30 with 10.20.30.1 as the gateway into the answer area in the order they must be entered. Not all commands are used.
POOL:
  [0] encapsulation dot1Q 30
  [1] switchport mode trunk
  [2] interface GigabitEthernet0/0.30
  [3] ip address 10.20.30.1 255.255.255.0
  [4] encapsulation dot1Q 30 native
  [5] interface vlan 30
KEY (ordered subset): [2] -> [0] -> [3]
why: Router-on-a-stick uses one subinterface per VLAN. The subinterface must be tied to its VLAN with encapsulation dot1Q before IOS accepts an IP address on it. switchport and interface vlan are switch commands, and the native keyword would make BR1 expect VLAN 30 untagged while BSW1 tags it.
TAKEAWAY: ROAS per VLAN: interface g0/0.N, encapsulation dot1Q N, ip address. The subinterface number is only a label; the VLAN comes from the encapsulation command. The physical interface must be up.

[b008] type=ms pick=2 domain=1 obj=1.1.a (Explain the role and function of network components — Routers)
Q: The branch has BR1, an ISR router, and BSW1, a Layer 2 access switch. Which two functions does BR1 perform that BSW1 does not? (Choose two.)
  * A. Forwarding packets between different IP subnets based on the destination IP address
        why: Routing between subnets is a Layer 3 function. BSW1 forwards frames only within a VLAN; VLAN-to-VLAN traffic must go through BR1.
  * B. Translating branch private addresses to a public address for internet traffic
        why: NAT/PAT runs on the router at the internet edge. A Layer 2 switch does not look at or rewrite IP addresses.
    C. Learning source MAC addresses to build a MAC address table
        why: MAC learning is the switch's core job. A router keeps an ARP table but does not learn MAC addresses to forward frames.
    D. Flooding frames whose destination MAC address is unknown
        why: Unknown-unicast flooding is switch behaviour. A router never floods; it routes or drops.
    E. Placing end devices into VLANs through access ports
        why: Access ports and VLAN membership are configured on the switch.
    F. Supplying PoE to IP phones
        why: Phones are powered by the switch ports they plug into, not by the router.
TAKEAWAY: Router: Layer 3 forwarding between subnets, WAN links, NAT, broadcast boundary. Layer 2 switch: MAC learning, forwarding, flooding and filtering inside VLANs, access ports, PoE. A Layer 3 switch adds routing with SVIs.

Q: Refer to the exhibit. Which two statements are true? (Choose two.)
EXHIBIT:
    BSW1# show cdp entry BSW2
    -------------------------
    Device ID: BSW2
    Entry address(es):
      IP address: 10.20.90.12
    Platform: cisco WS-C2960,  Capabilities: Switch IGMP
    Interface: GigabitEthernet0/2,  Port ID (outgoing port): GigabitEthernet0/1
    Holdtime : 155 sec
    
    Version :
    Cisco IOS Software, C2960 Software (C2960-LANBASEK9-M), Version 15.2(4)E7,
    RELEASE SOFTWARE (fc1)
    
    advertisement version: 2
    Native VLAN: 10
    Duplex: full
    Management address(es):
      IP address: 10.20.90.12
  * A. BSW1 connects to BSW2 through BSW1's own GigabitEthernet0/2
        why: 'Interface' is the local port on the switch where the command was run. 'Port ID (outgoing port)' is the neighbor's port.
  * B. BSW2 advertises 10.20.90.12 as its management address
        why: The entry and management addresses come from BSW2's own advertisement, here its VLAN 90 management SVI. CDP is a quick way to find a neighbor's address for SSH without a diagram.

        why: That is BSW1's local port. BSW2 sent the advertisement out its Gi0/1, shown as the Port ID.
    D. BSW2 may be several router hops away, because CDP travels in IP packets
        why: CDP is a Layer 2 protocol sent to a multicast MAC address and never routed. Every CDP neighbor is directly connected.
    E. The output comes from LLDP, which IOS runs on all ports by default
        why: This is CDP output. LLDP is disabled by default on IOS and is read with show lldp neighbors.
TAKEAWAY: show cdp neighbors: device, local interface, holdtime, capability, platform, port ID. show cdp neighbors detail or show cdp entry NAME adds IP addresses, IOS version, native VLAN and duplex.

[b010] type=mc domain=6 obj=6.2 (Compare traditional networks with controller-based networking)
Q: Today each branch router runs OSPF and builds its own routing table, and engineers configure each device separately over SSH. The company is evaluating a controller-based design. Which statement correctly compares the two approaches?
  * A. Traditionally each device runs its own control plane; a controller centralizes policy and programs devices through APIs
        why: In the current design every router computes its own view and is configured box by box. A controller holds a network-wide view, turns intent into device configuration and pushes it through southbound APIs.
    B. With a controller, the controller forwards all user traffic, so devices no longer need a data plane
        why: Forwarding stays on the routers and switches. The controller works in the control and management planes.
    C. Traditional networks already centralize the control plane in a management server, and controllers distribute it
        why: This reverses the two. Traditional devices each run their own control plane.
    D. A controller-based design requires removing every routing protocol from the network
        why: Controller-based fabrics still run routing in the underlay (SD-Access uses IS-IS, for example). The controller automates and orchestrates on top of it.
TAKEAWAY: Traditional: per-device control plane, per-box CLI, change by hand. Controller-based: central view and policy, templates, southbound APIs to devices, northbound REST APIs to apps; the data plane stays on the devices.

[b011] type=mc domain=1 obj=1.8 (Configure and verify IPv6 addressing and prefix)
Q: Refer to the exhibit. The branch is moving to dual stack, and BR1 Gi0/0 serves VLAN 10. PCs should build global IPv6 addresses with SLAAC, but they have only link-local IPv6 addresses and no IPv6 default gateway. IPv4 works. Which command fixes the problem?
EXHIBIT:
    BR1# show running-config | include ipv6
     ipv6 address FE80::1 link-local
     ipv6 address 2001:DB8:B1:10::1/64
    
    C:\> ipconfig
    
    Ethernet adapter Ethernet:
    
       Connection-specific DNS Suffix  . : branch.example
       Link-local IPv6 Address . . . . . : fe80::5d2a:91c4:7e10:3b6f%12
       IPv4 Address. . . . . . . . . . . : 10.20.10.37
       Subnet Mask . . . . . . . . . . . : 255.255.255.0
       Default Gateway . . . . . . . . . : 10.20.10.1
  * A. ipv6 unicast-routing in global configuration mode
        why: Without it IOS acts as an IPv6 host: it sends no router advertisements and forwards no IPv6 packets. The filter shows no ipv6 unicast-routing line. Once enabled, BR1 advertises 2001:db8:b1:10::/64 and the PCs autoconfigure with FE80::1 as gateway.
    B. ipv6 enable on Gi0/0
        why: Configuring an IPv6 address already enables IPv6 on the interface. ipv6 enable only creates a link-local address, and BR1 already has one.
    C. ipv6 address autoconfig on Gi0/0
        why: This makes BR1 itself a SLAAC client that learns an address from another router. BR1 would still send no RAs to the PCs.
    D. ipv6 nd managed-config-flag on Gi0/0
        why: This RA flag tells hosts to use stateful DHCPv6. BR1 is not sending RAs at all, and the branch has no DHCPv6 server.
TAKEAWAY: Router IPv6 basics: ipv6 unicast-routing (global), then interface addresses. RAs then go out LAN interfaces automatically, and hosts use SLAAC with the router's link-local address as default gateway.

[b012] type=mc domain=2 obj=2.6 (Describe Cisco Wireless Architectures and AP modes)
Q: The branch has no local wireless controller; its lightweight APs join the WLC at HQ across the WAN. Staff traffic must be switched onto VLAN 10 at the branch instead of being tunneled to HQ, and connected clients must stay online if the WAN fails. Which AP mode meets these requirements?
  * A. FlexConnect
        why: FlexConnect APs keep CAPWAP control to the central WLC but can switch WLAN traffic locally onto branch VLANs. If the WAN drops, they go standalone and keep serving connected clients on locally switched WLANs.
    B. Local
        why: Local mode tunnels all client data in CAPWAP to the WLC, so staff traffic would hairpin through HQ, and clients drop when the WAN fails.
    C. Bridge
        why: Bridge (mesh) mode links APs to each other wirelessly to extend coverage. It does not provide local switching for a WAN-connected branch.
    D. Monitor
        why: A monitor-mode AP serves no clients at all; it only scans channels for rogues and intrusion detection.
TAKEAWAY: AP modes: local (default, client data in CAPWAP to the WLC), FlexConnect (branch, local switching, survives WAN loss), monitor, sniffer, rogue detector, SE-Connect, bridge/mesh.

[b013] type=ms pick=2 domain=1 obj=1.3.a (Compare physical interface and cabling types — Single-mode fiber, multimode fiber, copper)
Q: BSW1 needs a 1-Gb/s uplink to a new switch in the warehouse, a 160 m cable run from the branch wiring closet. Which two cabling options support this link? (Choose two.)
  * A. 1000BASE-SX transceivers over multimode fiber
        why: 1000BASE-SX reaches roughly 220 to 550 m over multimode fiber depending on the fiber grade, so 160 m is well within range.
  * B. 1000BASE-LX transceivers over single-mode fiber
        why: 1000BASE-LX over single-mode fiber reaches several kilometers. It is more reach than needed, but it works.
    C. 1000BASE-T over Cat 6 UTP
        why: Twisted-pair Ethernet is limited to 100 m per segment, whatever the cable category.
    D. 1000BASE-T over Cat 6a shielded cable
        why: Better cable improves noise immunity and supports 10GBASE-T, but the 100 m limit still applies.
    E. A Cat 5e crossover cable, with auto-MDIX disabled on both ends
        why: Crossover or straight-through only changes which pairs transmit and receive. It does not extend the 100 m limit.
TAKEAWAY: Copper twisted pair (10BASE-T to 10GBASE-T): 100 m. Multimode fiber (SX, larger core, cheaper optics): hundreds of meters inside buildings and campuses. Single-mode fiber (LX/LR, laser, 9-micron core): kilometers.

[b014] type=mc domain=2 obj=2.2.a (Configure and verify interswitch connectivity — Trunk ports)
Q: Refer to the exhibit. Guest users on BSW2 Fa0/13-20 (VLAN 50) get no DHCP lease. BSW2 Gi0/1 trunks to BSW1 Gi0/2, and BSW1 Gi0/1 trunks to BR1, which routes VLAN 50 on Gi0/0.50. Staff and voice VLANs work, and both switches use VTP transparent mode. What is the cause?
EXHIBIT:
    BSW1# show interfaces trunk
    Port        Mode             Encapsulation  Status        Native vlan
    Gi0/1       on               802.1q         trunking      10
    Gi0/2       on               802.1q         trunking      10
    
    Port        Vlans allowed on trunk
    Gi0/1       10,20,40,50,90
    Gi0/2       10,20,40,50,90
    
    Port        Vlans allowed and active in management domain
    Gi0/1       10,20,40,90
    Gi0/2       10,20,40,90
    
    Port        Vlans in spanning tree forwarding state and not pruned
    Gi0/1       10,20,40,90
    Gi0/2       10,20,40,90
  * A. VLAN 50 does not exist in BSW1's VLAN database, so BSW1 does not forward its frames
        why: VLAN 50 is allowed but missing from 'allowed and active in management domain'. A switch only carries VLANs that exist locally, so guest frames die at BSW1. Creating it with vlan 50 on BSW1 fixes the path.
    B. VLAN 50 is not in the allowed list on BSW1's trunks
        why: Both trunks list 10,20,40,50,90 as allowed. The allowed list is not the problem.
    C. The trunks use native VLAN 10, which blocks tagged VLAN 50 frames
        why: The native VLAN only decides which VLAN crosses the link untagged. Every other allowed VLAN is tagged and carried normally.
    D. VTP pruning removed VLAN 50 because no BSW1 access port uses it
        why: Pruning does not apply in transparent mode, and pruning would only affect the last list. VLAN 50 is already missing from the 'active' list.
TAKEAWAY: show interfaces trunk has three VLAN lists: allowed (configured), allowed and active (also exists locally), forwarding and not pruned (also STP forwarding). A VLAN dropping out of the second list does not exist on that switch.

[b015] type=ms pick=3 domain=6 obj=6.7 (Recognize components of JSON-encoded data)
Q: Refer to the exhibit. A script receives this record for BR1 from the branch controller. Which three statements are true? (Choose three.)
EXHIBIT:
    {
      "hostname": "BR1",
      "managementIp": "10.20.90.1",
      "reachable": true,
      "uptimeDays": "212",
      "interfaces": [
        { "name": "GigabitEthernet0/0", "vlan": 10, "ipv4": "10.20.10.1" },
        { "name": "GigabitEthernet0/0.20", "vlan": 20, "ipv4": "10.20.20.1" }
      ],
      "location": null
    }
  * A. The value of "interfaces" is an array that contains two objects
        why: Square brackets mark an array; each element in braces is an object with its own key/value pairs.
  * B. The value of "reachable" is a Boolean
        why: true is written without quotes, which makes it the JSON Boolean literal rather than a string.
  * C. The value of "vlan" is a number in both interface objects
        why: 10 and 20 have no quotes, so they are numbers.
    D. The value of "uptimeDays" is a number
        why: "212" is in double quotes, so it is a string. A script that does math on it must convert it first.
    E. The record is invalid because "location" has no value
        why: null is a valid JSON value meaning 'no value'. The record parses correctly.
    F. The outermost element is an array of key/value pairs
        why: The record starts with a brace, so it is an object. Arrays use square brackets.

[b016] type=mc domain=1 obj=1.13.d (Describe switching concepts — MAC address table)

[b018] type=mc domain=1 obj=1.5 (Compare TCP to UDP)
Q: A branch PC sends three 1000-byte TCP segments to an HQ server with relative sequence numbers 1, 1001 and 2001. The segment with sequence number 1001 is lost; the other two arrive. Which acknowledgment number does the server send after the third segment arrives?
  * A. 1001
        why: TCP acknowledgments are cumulative and name the next byte the receiver expects. Bytes 1 to 1000 arrived and byte 1001 did not, so the server keeps asking for 1001 even though bytes 2001 to 3000 are buffered.
    B. 2001
        why: That would acknowledge bytes 1001 to 2000, which never arrived.
    C. 3001
        why: That would acknowledge everything, including the lost segment, and the PC would never resend it.
    D. 1000
        why: The acknowledgment number is the next byte expected, not the last byte received.
TAKEAWAY: Sequence number = first byte in the segment; ACK = next byte expected (cumulative). A gap holds the ACK in place, and duplicate ACKs or a timeout trigger a resend. UDP has no sequencing, ACKs or retransmission.

[b042] type=mc domain=1 obj=1.11.c (Describe wireless principles — RF)

  * A. 25 dB
        why: SNR is the signal minus the noise floor: -67 - (-92) = 25 dB. The signal is 25 dB above the noise, which is generally enough for data and voice.
    B. -25 dB
        why: This subtracts the signal from the noise. A usable link always has the signal above the noise, so SNR is positive.
    C. 159 dB
        why: Adding the two magnitudes is not meaningful. In dB, a ratio is found by subtraction.
    D. 67 dB
        why: 67 is just the signal level with the sign dropped. SNR compares the signal with the noise floor.

        why: A shaper buffers excess traffic and releases it at the contracted rate, so the ISP policer never sees traffic above 100 Mbps. The cost is some extra delay instead of drops.
    B. Policing to 100 Mbps, so traffic above the contract is dropped on BR1
        why: An outbound policer drops or re-marks excess traffic just as the ISP's does. The drops simply move to BR1.
    C. Marking all branch traffic DSCP EF so the ISP gives it priority
        why: Marking only labels packets. It does not limit the rate, and the ISP is unlikely to honor customer EF on internet traffic.
    D. The bandwidth 100000 interface command
        why: bandwidth only informs routing protocol metrics and QoS calculations. It does not limit how fast the interface sends.
TAKEAWAY: Shaping = buffer and delay the excess (smooth, adds latency), used outbound toward a slower contract. Policing = drop or re-mark the excess, typical at the provider edge.

[b087] type=mc domain=5 obj=5.1 (Define key security concepts (threats, vulnerabilities, exploits, and mitigation techniques))
Q: BR1 runs an IOS release with a published flaw in its HTTP server, and ip http server is enabled on the internet-facing interface. A researcher posts a script that sends crafted HTTP requests to gain privilege level 15. Which statement uses the security terms correctly?
  * A. The flaw is the vulnerability, the script is the exploit, and patching or disabling the HTTP server is the mitigation
        why: A vulnerability is a weakness, an exploit is the code or technique that takes advantage of it, and a mitigation removes or reduces it. No ip http server, or an upgrade, removes the attack surface.
    B. The script is the vulnerability, the flaw is the exploit, and the HTTP server is the mitigation
        why: The terms are swapped. The weakness in the code is the vulnerability, and the script that abuses it is the exploit.
    C. The flaw is the threat, the script is the vulnerability, and the researcher is the exploit
        why: A threat is a potential danger, such as an attacker who might use the script. The script itself is the exploit, and a person is never an exploit.
    D. The HTTP server is the exploit, and enabling HTTPS instead is the vulnerability
        why: A service is not an exploit. Moving to HTTPS encrypts the session but would not fix a flaw in the same server code.
TAKEAWAY: Vulnerability = weakness. Exploit = what uses it. Threat = who or what might. Mitigation = what reduces the risk. Turn off services you do not use.

[b088] type=mc domain=3 obj=3.3.a (Configure and verify IPv4 and IPv6 static routing — Default route)

        why: With only an exit interface on a multi-access network, BR1 sends an ARP request for every destination address. This works only if the ISP router answers with proxy ARP, and it bloats the ARP cache, so a next hop is recommended on Ethernet.
    B. It behaves exactly like a default route via 203.0.113.1
        why: With a next hop, BR1 ARPs once for 203.0.113.1. With only an exit interface, it ARPs for each final destination.
    C. IOS rejects the command because Ethernet static routes require a next-hop address
        why: IOS accepts it. The route shows as directly connected, which works on point-to-point links but is a poor choice on Ethernet.
    D. The route is installed with AD 0, so it overrides connected routes
        why: A static route to an exit interface still has AD 1, and it cannot override connected routes, which are more specific anyway.

[b089] type=mc domain=4 obj=4.4 (Explain the function of SNMP in network operations)
Q: The HQ network management station polls BR1's interface counters every five minutes, and it must also be told immediately when a WAN link goes down. Which statement describes the SNMP communication?
  * A. The NMS sends Get requests to BR1's agent on UDP 161, and BR1 sends traps or informs to the NMS on UDP 162
        why: Polling is manager-to-agent Get/GetNext/GetBulk on UDP 161. Unsolicited events go agent-to-manager as traps (no acknowledgment) or informs (acknowledged) on UDP 162.
    B. BR1 sends unsolicited Get responses every five minutes to the NMS on UDP 162
        why: Responses only answer requests. The NMS controls the polling interval, and UDP 162 is for notifications.
    C. Traps need SNMPv3, because SNMPv2c supports only polling
        why: SNMPv2c supports traps and adds informs. SNMPv3 adds authentication and encryption, not notifications.
    D. The NMS reads the counters with Set requests on UDP 162
        why: Set changes values on the agent, and agents listen on UDP 161. Reading uses Get.
TAKEAWAY: SNMP: manager polls the agent (Get, Set) on UDP 161; the agent notifies the manager (Trap, Inform) on UDP 162. Data lives in the MIB, identified by OIDs.

[b090] type=mc domain=3 obj=3.5 (Describe the purpose, functions, and concepts of first hop redundancy protocols)
Q: Branch PCs use 10.20.10.1, the VRRP virtual address shared by BR1 (master) and BR2 (backup), as their default gateway. BR1 loses power. What happens on the branch PCs?
  * A. Nothing changes on the PCs; BR2 takes over the same virtual IP and virtual MAC and announces it with gratuitous ARP
        why: The PCs' gateway IP and its ARP entry still point to the virtual MAC, which BR2 now owns. Its gratuitous ARP updates the switches' MAC tables so frames reach the new master.
    B. The PCs must renew their DHCP leases to learn BR2 as the new gateway
        why: The gateway address handed out by DHCP is the virtual IP, which does not change. An FHRP exists so hosts need no change.
    C. Traffic stops until each PC's ARP entry for the gateway ages out and is relearned
        why: The virtual MAC moves with the virtual IP, so the existing ARP entries stay correct.

        why: VRRP does not rely on ICMP redirects. Hosts keep using the virtual address.

[b092] type=mc domain=3 obj=3.4.b (Configure and verify single area OSPFv2 — Point-to-point)

  * A. ip ospf network point-to-point
        why: With only two routers on the segment, the point-to-point network type skips the DR/BDR election and wait timer and goes straight to FULL. It must match on both ends.
    B. ip ospf priority 0
        why: With priority 0 on both routers, no DR can be elected. On a broadcast network the neighbors then stay in 2-WAY and never exchange LSAs.

        why: Cost only affects path selection. Gi interfaces already cost 1, and the network type stays broadcast.
    D. ip ospf hello-interval 1
        why: Faster hellos speed up neighbor-loss detection but keep the broadcast network type and its DR election. They also must match on both ends.

[b093] type=mc domain=5 obj=5.8 (Compare authentication, authorization, and accounting concepts)
Q: Branch routers check administrator logins against a TACACS+ server at HQ. A junior technician logs in successfully, but when she types configure terminal the router replies 'Command authorization failed.' Which AAA function denied the command?
  * A. Authorization
        why: Authorization decides what an authenticated user may do. TACACS+ can authorize each command separately, which is why it is preferred for device administration.
    B. Authentication
        why: Authentication proves identity. It succeeded, because she logged in.
    C. Accounting
        why: Accounting records what users did, such as session times and commands entered. It does not allow or deny anything.
    D. TACACS+ payload encryption
        why: TACACS+ encrypts the whole payload, but that protects the exchange. It is not the function that refuses commands.
