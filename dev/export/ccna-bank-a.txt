[a001] type=mc domain=2 obj=2.5.b (Interpret basic operations of Rapid PVST+ Spanning Tree Protocol — Port states and roles)
Q: Refer to the exhibit. ACC-3 uplinks to DIST-1 on Gi0/1 and to DIST-2 on Gi0/2. DIST-1 is the root bridge for VLAN 10 and DIST-2 reaches the root over its own direct 1-Gb/s link. The fiber on ACC-3 Gi0/1 is cut. What happens on ACC-3 in VLAN 10?
EXHIBIT:
    ACC-3# show spanning-tree vlan 10
    VLAN0010
      Spanning tree enabled protocol rstp
      Root ID    Priority    24586
                 Address     0001.4200.0100
                 Cost        4
                 Port        25 (GigabitEthernet0/1)
                 Hello Time   2 sec  Max Age 20 sec  Forward Delay 15 sec
    
      Bridge ID  Priority    32778  (priority 32768 sys-id-ext 10)
                 Address     0001.4200.0300
                 Hello Time   2 sec  Max Age 20 sec  Forward Delay 15 sec
                 Aging Time  300 sec
    
    Interface           Role Sts Cost      Prio.Nbr Type
    ------------------- ---- --- --------- -------- --------------
    Gi0/1               Root FWD 4         128.25   P2p
    Gi0/2               Altn BLK 4         128.26   P2p
  * A. Gi0/2 becomes the root port and starts forwarding almost at once, with a root path cost of 8
        why: An RSTP alternate port is a pre-computed backup root port. When the root port fails it is promoted and moved to forwarding without timers. The new cost is DIST-2's cost of 4 plus Gi0/2's own cost of 4.
    B. Gi0/2 becomes the root port but spends 30 seconds in listening and learning before it forwards
        why: That is legacy 802.1D behaviour (2 x 15-second forward delay). Rapid PVST+ promotes an alternate port to root port immediately.
    C. ACC-3 declares itself root for VLAN 10 until DIST-1's BPDUs reach it again
        why: ACC-3 still receives superior BPDUs on Gi0/2. In RSTP, DIST-2 sends BPDUs carrying DIST-1 as root, and a priority of 32778 can never beat 24586.
    D. Gi0/2 becomes a backup port and remains in the discarding state
        why: A backup port is a redundant link to a segment the same switch already serves as designated, such as two ports on one hub. Gi0/2 leads to another switch, so it is alternate and becomes root port here.
TAKEAWAY: RSTP alternate port = backup path to the root via another switch; it takes over as root port instantly. Root path cost = neighbor's advertised cost + local port cost.

[a002] type=mc domain=1 obj=1.6 (Configure and verify IPv4 addressing and subnetting)
Q: The new staff VLAN on DIST-1 must hold 450 hosts. The address plan gives it the next free block starting at 10.40.4.0, and the SVI must take the first usable address. Which configuration gives VLAN 10 the smallest subnet that fits?
  * A. interface vlan 10 / ip address 10.40.4.1 255.255.254.0
        why: A /23 has 9 host bits: 2^9 - 2 = 510 usable addresses, enough for 450. 10.40.4.0 is on a /23 boundary (4 is a multiple of 2), so .4.1 is the first host.
    B. interface vlan 10 / ip address 10.40.4.1 255.255.255.0
        why: A /24 holds only 254 hosts, well short of 450.
    C. interface vlan 10 / ip address 10.40.4.1 255.255.252.0
        why: A /22 (1022 hosts) would work but is twice as large as needed. The question asks for the smallest subnet that fits.
    D. interface vlan 10 / ip address 10.40.4.0 255.255.254.0
        why: 10.40.4.0 is the network address of 10.40.4.0/23. IOS rejects it as an interface address (bad mask / network address).
TAKEAWAY: Hosts = 2^h - 2. 450 hosts needs h = 9, which is /23 (255.255.254.0), block size 2 in the third octet.

[a003] type=ms pick=2 domain=6 obj=6.7 (Recognize components of JSON-encoded data)
Q: Refer to the exhibit. A script pulls this inventory record for an access switch from the campus controller. Which two statements about the data are true? (Choose two.)
EXHIBIT:
    {
      "switch": "ACC-3",
      "mgmt": {
        "ip": "10.40.100.13",
        "vlan": 100
      },
      "ports": [
        { "name": "Gi0/1", "mode": "trunk",  "enabled": true },
        { "name": "Fa0/7", "mode": "access", "vlan": 10, "enabled": true },
        { "name": "Fa0/8", "mode": "access", "vlan": 10, "enabled": false }
      ]
    }
  * A. The value of "ports" is an array that holds three objects
        why: Square brackets mark an array; each element inside is an object in curly braces, and there are three of them.
  * B. The value of "enabled" is a Boolean, not a string
        why: true and false appear without quotes, so they are JSON Booleans. "true" in quotes would be a string.
    C. The value of "mgmt" is an array of two strings
        why: "mgmt" is an object (curly braces) with two key/value pairs. One value is a string ("10.40.100.13") and the other is a number (100).
    D. The VLAN value 100 is a string because VLAN IDs are labels
        why: 100 has no quotes, so JSON treats it as a number. Only quoted values are strings.
    E. The record is invalid because the Gi0/1 object has no "vlan" key
        why: JSON does not require objects in an array to share the same keys. Missing keys are a data-model question, not a syntax error.
    F. The outermost structure of the record is an array
        why: The record starts with { and ends with }, so the outermost structure is an object.
TAKEAWAY: JSON: {} object of key/value pairs, [] ordered array, quoted text = string, bare numbers = number, true/false = Boolean, null = null. Keys are always quoted strings.

[a004] type=mc domain=1 obj=1.13.c (Describe switching concepts — Frame flooding)
Q: Refer to the exhibit. On ACC-2, Fa0/1-12 are access ports in VLAN 10, Fa0/13-24 are access ports in VLAN 20, and Gi0/1 is a trunk allowing all VLANs. PC1 on Fa0/1 sends a unicast frame to 00e0.4c00.0601. What does ACC-2 do with the frame?
EXHIBIT:
    ACC-2# show mac address-table
              Mac Address Table
    -------------------------------------------
    
    Vlan    Mac Address       Type        Ports
    ----    -----------       --------    -----
      10    0001.4200.0100    DYNAMIC     Gi0/1
      10    00e0.4c00.0301    DYNAMIC     Fa0/1
      10    00e0.4c00.0401    DYNAMIC     Fa0/2
      20    0001.4200.0100    DYNAMIC     Gi0/1
      20    00e0.4c00.0501    DYNAMIC     Fa0/13
    Total Mac Addresses for this criterion: 5
  * A. It floods the frame out every other forwarding port in VLAN 10, including trunk Gi0/1
        why: 00e0.4c00.0601 is not in the VLAN 10 table, so it is an unknown unicast. The switch floods it within VLAN 10 only, out every port except the one it came in on, and the trunk carries it tagged for VLAN 10.
    B. It drops the frame because the destination MAC address is unknown
        why: Switches never drop unknown unicast by default; they flood it so the frame can still reach the host, then learn its port when it replies.
    C. It floods the frame out every port on the switch in both VLAN 10 and VLAN 20
        why: Flooding is bounded by the VLAN. A frame received in VLAN 10 is never sent out VLAN 20 access ports.
    D. It forwards the frame only out Gi0/1 toward the default gateway's MAC address
        why: A switch does not use the default gateway for Layer 2 forwarding. The destination is unknown, so the frame is flooded in VLAN 10, not sent to one port.
TAKEAWAY: Known unicast: forward out one port. Unknown unicast, broadcast and (by default) multicast: flood out all ports in the same VLAN except the ingress port.

[a005] type=mc domain=2 obj=2.2.c (Configure and verify interswitch connectivity — Native VLAN)
Q: Refer to the exhibit. The campus standard is native VLAN 99 on every trunk. ACC-3 Gi0/1 is cabled to DIST-1 Gi1/0/3. Which action fixes the problem and keeps the standard?
EXHIBIT:
    ACC-3#
    %CDP-4-NATIVE_VLAN_MISMATCH: Native VLAN mismatch discovered on
     GigabitEthernet0/1 (99), with DIST-1 GigabitEthernet1/0/3 (1).
    
    ACC-3# show interfaces trunk
    Port        Mode             Encapsulation  Status        Native vlan
    Gi0/1       on               802.1q         trunking      99
    
    Port        Vlans allowed on trunk
    Gi0/1       10,20,30,99,100
  * A. On DIST-1 Gi1/0/3, enter switchport trunk native vlan 99
        why: The message shows ACC-3 uses native 99 and DIST-1 Gi1/0/3 uses 1. Setting DIST-1's trunk to native 99 makes both ends match and follows the standard.
    B. On ACC-3 Gi0/1, enter switchport trunk native vlan 1
        why: Both ends would then match and the CDP message would stop, but the trunk would use native VLAN 1, which breaks the campus standard.
    C. On DIST-1 Gi1/0/3, enter switchport trunk allowed vlan add 99
        why: The allowed list controls which VLANs cross the trunk. It does not change which VLAN is sent untagged, so the native mismatch remains.
    D. On ACC-3 Gi0/1, enter switchport nonegotiate
        why: This only turns off DTP. The link is already trunking; the problem is the untagged VLAN on each end.
TAKEAWAY: Native VLAN must match on both ends of an 802.1Q trunk. A mismatch merges the two VLANs' untagged traffic; CDP reports it with %CDP-4-NATIVE_VLAN_MISMATCH.

[a006] type=mc domain=1 obj=1.10 (Verify IP parameters for Client OS (Windows, Mac OS, Linux))
Q: Refer to the exhibit. A technician statically addressed this workstation in the engineering VLAN, whose gateway SVI is 10.40.21.129/25. The workstation can ping other hosts in its VLAN but cannot reach anything in other buildings. What is the cause?
EXHIBIT:
    C:\> ipconfig /all
    
    Ethernet adapter Ethernet:
    
       Connection-specific DNS Suffix  . :
       Physical Address. . . . . . . . . : 3C-52-82-1A-7E-04
       DHCP Enabled. . . . . . . . . . . : No
       IPv4 Address. . . . . . . . . . . : 10.40.21.130(Preferred)
       Subnet Mask . . . . . . . . . . . : 255.255.255.128
       Default Gateway . . . . . . . . . : 10.40.21.1
       DNS Servers . . . . . . . . . . . : 10.40.0.53
  * A. The default gateway is outside the host's subnet; it should be 10.40.21.129
        why: 10.40.21.130/25 lives in 10.40.21.128/25 (.129-.254). 10.40.21.1 is in 10.40.21.0/25, so the PC cannot ARP for it and has no working path off its subnet.
    B. The subnet mask is invalid because a 10.x.x.x address requires 255.0.0.0
        why: Classful masks have not applied for decades. A /25 on a 10.x address is perfectly valid and matches the SVI.
    C. DHCP is disabled, so the workstation has no route to other subnets
        why: Static addressing works fine if the values are right. DHCP is only one way to receive the gateway; the gateway entered here is the problem.
    D. The DNS server is on a different subnet, which blocks off-subnet traffic
        why: DNS servers are normally on other subnets. DNS affects name lookups, not whether packets can leave the subnet.
TAKEAWAY: Check a client's IP, mask and gateway together: the gateway must be an address inside the host's own subnet.

[a007] type=mc domain=6 obj=6.5 (Describe characteristics of REST-based APIs (authentication types, CRUD, HTTP verbs, and data encoding))
Q: The campus controller exposes each switch port as a resource at /api/v1/interfaces/{id}. An engineer must change only the description of one port, sending just the description field and leaving every other attribute as it is. Which HTTP method fits?
  * A. PATCH
        why: PATCH applies a partial update: only the fields in the body change, and everything else on the resource is kept.
    B. PUT
        why: PUT replaces the whole resource with the representation in the body. Sending only the description could reset or remove the attributes that were left out.
    C. POST
        why: POST creates a new resource (or triggers an action) under a collection. It is not the method for editing one field of an existing port.
    D. GET
        why: GET only reads a resource. It never changes anything on the server.
TAKEAWAY: CRUD to HTTP: Create = POST, Read = GET, Update = PUT (replace) or PATCH (partial), Delete = DELETE.

[a008] type=mc domain=2 obj=2.6 (Describe Cisco Wireless Architectures and AP modes)
Q: Security staff want one lightweight AP in the main library to stop serving clients and spend all of its time scanning every channel for rogue APs and wireless attack signatures, reporting what it finds to the WLC. Which AP mode should be set?
  * A. Monitor
        why: Monitor mode turns the AP into a dedicated sensor. It serves no clients and scans all channels for rogue detection, wIPS and location data.
    B. Local
        why: Local mode is the default. The AP serves clients on its channel and only goes off-channel briefly to scan, so it is not dedicated to detection.
    C. FlexConnect
        why: FlexConnect lets an AP across a WAN keep serving clients and switch traffic locally if the link to the WLC fails. It still serves clients.
    D. Bridge
        why: Bridge mode builds mesh or point-to-point wireless backhaul links between APs. It has nothing to do with dedicated rogue scanning.
TAKEAWAY: AP modes: local (default, serves clients, CAPWAP to WLC), FlexConnect (remote sites, local switching), monitor (sensor only), sniffer (captures for an analyzer), bridge (mesh), SE-Connect (spectrum analysis).

[a009] type=mc domain=1 obj=1.4 (Identify interface and cable issues (collisions, errors, mismatch duplex, and/or speed))
Q: Refer to the exhibit. A print server cabled directly to ACC-6 Fa0/14 is slow. Its NIC was hard-coded to 100 Mb/s full duplex; the switch port was left at its defaults. What explains the counters, and what fixes the problem?
EXHIBIT:
    ACC-6# show interfaces fastEthernet0/14
    FastEthernet0/14 is up, line protocol is up (connected)
      Hardware is Fast Ethernet, address is 00a1.b2c3.4d0e
      MTU 1500 bytes, BW 100000 Kbit/sec, DLY 100 usec,
         reliability 255/255, txload 3/255, rxload 2/255
      Encapsulation ARPA, loopback not set
      Half-duplex, 100Mb/s, media type is 10/100BaseTX
      ...
         0 input errors, 0 CRC, 0 frame, 0 overrun, 0 ignored
         48211 packets output, 6930214 bytes, 0 underruns
         0 output errors, 2215 collisions, 3 interface resets
         0 babbles, 836 late collision, 0 deferred
  * A. Autonegotiation failed and the switch fell back to half duplex; set duplex full and speed 100 on Fa0/14
        why: With the peer hard-coded, the switch senses 100 Mb/s but cannot learn duplex, so it falls back to half. It then sees collisions, including late ones, while the full-duplex NIC never waits. Matching the settings ends the mismatch.
    B. The speeds do not match; set speed 10 on Fa0/14
        why: Both sides already run 100 Mb/s, as the output shows. A real speed mismatch normally keeps the link down entirely, and 10 Mb/s would make it slower.
    C. Electrical noise is corrupting frames; replace the cable with shielded cable
        why: Noise shows up as CRC and input errors, and both are zero here. The errors are collisions on a half-duplex port.
    D. Too many devices share the collision domain; replace the hub on Fa0/14 with a switch
        why: The stem says the print server connects directly. Collisions on a point-to-point link mean one side is half duplex, not that the segment is crowded.
TAKEAWAY: Duplex mismatch fingerprint: the half-duplex side logs collisions and late collisions; the full-duplex side logs CRC errors and runts. Hard-code both ends or let both negotiate.

[a010] type=mc domain=1 obj=1.9.d (Describe IPv6 address types — Modified EUI 64)
Q: The VLAN 30 SVI on DIST-2 has MAC address 0c2a.7f31.4b90 and is configured with ipv6 address 2001:db8:acad:30::/64 eui-64. Which global unicast address does the SVI get?
  * A. 2001:DB8:ACAD:30:E2A:7FFF:FE31:4B90
        why: Split the MAC into 0c2a7f and 314b90, insert FFFE between them, and flip the 7th bit of the first byte: 0x0C (0000 1100) becomes 0x0E (0000 1110). Interface ID 0E2A:7FFF:FE31:4B90.
    B. 2001:DB8:ACAD:30:C2A:7FFF:FE31:4B90
        why: FFFE was inserted correctly but the universal/local (7th) bit was not flipped. Modified EUI-64 always inverts it, so 0C becomes 0E.
    C. 2001:DB8:ACAD:30:E2A:FFFE:7F31:4B90
        why: FFFE belongs in the exact middle of the 48-bit MAC, after the third byte (0c2a7f), not after the second.
    D. 2001:DB8:ACAD:30::E2A:7F31:4B90
        why: This drops FFFE entirely. Modified EUI-64 builds a 64-bit ID by inserting FFFE; a 48-bit MAC alone cannot fill it.
TAKEAWAY: Modified EUI-64: split the MAC in half, insert FFFE, flip bit 7 of the first byte (00 to 02, 0C to 0E, 52 to 50).

[a011] type=mc domain=2 obj=2.1.a (Configure and verify VLANs (normal range) spanning multiple switches — Access ports (data and voice))
Q: Refer to the exhibit. An IP phone is cabled to ACC-4 Fa0/7, and a staff PC is cabled to the phone's PC port. How do the two devices' frames arrive on Fa0/7?
EXHIBIT:
    ACC-4# show running-config interface fastEthernet0/7
    interface FastEthernet0/7
     description Room 2-114 phone + PC
     switchport access vlan 10
     switchport mode access
     switchport voice vlan 30
     spanning-tree portfast
    end
  * A. Phone frames carry an 802.1Q tag for VLAN 30; PC frames arrive untagged and go into VLAN 10
        why: With a voice VLAN, the switch tells the phone (via CDP) to tag voice traffic with VLAN 30. The PC's frames pass through the phone untagged and land in the access VLAN, 10.
    B. Both arrive untagged, and the switch sorts them into VLANs 10 and 30 by MAC address
        why: An access port does not sort untagged frames into VLANs by MAC. The voice VLAN works because the phone tags its frames.
    C. Both arrive tagged: the phone uses VLAN 30 and the PC uses VLAN 10
        why: The PC is unaware of VLANs and sends untagged frames. Only the phone tags, and only with the voice VLAN.
    D. Fa0/7 becomes a full trunk to the phone carrying all VLANs, with the PC tagged in VLAN 10
        why: The port stays in access mode; show interfaces trunk will not list it. It accepts only untagged data-VLAN frames and frames tagged with the voice VLAN.
TAKEAWAY: Access port + voice VLAN: data VLAN untagged for the PC, voice VLAN tagged by the phone (learned via CDP or LLDP-MED). The port is still an access port.

[a012] type=mc domain=6 obj=6.2 (Compare traditional networks with controller-based networking)
Q: The campus team configures each of its 140 switches over CLI, one device at a time. It is evaluating a controller-based design for the new buildings. Which statement correctly describes the controller-based approach?
  * A. Intent and policy are defined once on a central controller, which programs the devices through southbound APIs
        why: The controller centralizes the management and much of the control logic, then pushes configuration to every device. Engineers stop touching each box individually.
    B. All user traffic is forwarded through the controller, which replaces the switches' data plane
        why: The data plane stays on the switches; frames and packets are still forwarded in hardware on each device. Sending every frame through a controller would not scale.
    C. Devices no longer need management IP addresses, because the controller reaches them over Layer 2
        why: The controller talks to devices over IP using protocols such as NETCONF, RESTCONF or SSH, so devices still need management addresses.
    D. Switches keep no forwarding tables, because the controller makes every forwarding decision
        why: Devices still hold MAC, routing and forwarding tables. The controller programs policy; it does not replace per-packet forwarding on each device.
TAKEAWAY: Traditional: distributed control plane, box-by-box config. Controller-based: centralized policy and management, devices programmed via southbound APIs, data plane stays on the devices.

[a013] type=mc domain=1 obj=1.11.a (Describe wireless principles — Nonoverlapping Wi-Fi channels)
Q: Three APs cover overlapping areas of a lecture hall in a US deployment using the 2.4-GHz band (channels 1-11). AP-1 uses channel 1 and AP-2 uses channel 6. Which channel should AP-3 use so that none of the three APs overlap?
  * A. 11
        why: 2.4-GHz channels are 5 MHz apart but about 22 MHz wide, so only channels five apart do not overlap. In the US that set is 1, 6 and 11.
    B. 3
        why: Channel 3 overlaps both channel 1 and channel 6, adding interference to both APs.
    C. 8
        why: Channel 8 is only two channels (10 MHz) from 6, so their spectrum overlaps heavily.

TAKEAWAY: 2.4 GHz nonoverlapping channels in the US: 1, 6, 11. Use 5 GHz when you need more clean channels.

[a014] type=mc domain=2 obj=2.4 (Configure and verify (Layer 2/Layer 3) EtherChannel (LACP))
Q: Refer to the exhibit. ACC-5 Gi0/1-2 connect to DIST-2 Gi0/1-2. Both switches have channel-group 1 mode passive on both ports. Which change lets the bundle form using LACP?
EXHIBIT:
    ACC-5# show etherchannel summary
    Flags:  D - down        P - bundled in port-channel
            I - stand-alone s - suspended
            R - Layer3      S - Layer2
            U - in use      f - failed to allocate aggregator
    
    Number of channel-groups in use: 1
    Number of aggregators:           1
    
    Group  Port-channel  Protocol    Ports
    ------+-------------+-----------+-----------------------------
    1      Po1(SD)       LACP        Gi0/1(I) Gi0/2(I)
  * A. On ACC-5 Gi0/1-2, change to channel-group 1 mode active
        why: Passive only answers LACP; it never starts the negotiation. With one side active and the other passive, LACP runs and the ports bundle (flags P, Po1 SU).
    B. On ACC-5 Gi0/1-2, change to channel-group 1 mode desirable
        why: Desirable is a PAgP mode. PAgP and LACP cannot negotiate with each other, so this cannot bundle with DIST-2's LACP passive ports.
    C. On ACC-5 Gi0/1-2, change to channel-group 1 mode on
        why: Mode on sends no negotiation frames and bundles only with a peer that is also on. Against LACP passive it does not form a working channel.
    D. Shut down and re-enable interface Port-channel1 on both switches
        why: Bouncing the port-channel changes nothing. Passive/passive will still never send the first LACP packet.
TAKEAWAY: EtherChannel modes that form a channel: LACP active+active or active+passive; PAgP desirable+desirable or desirable+auto; on+on. Passive+passive and auto+auto never form.

[a015] type=build ordered=false domain=1 obj=1.5 (Compare TCP to UDP)
Q: The campus is moving its phone system to VoIP, which carries the audio stream in RTP over UDP. Drag the characteristics of UDP into the answer area. Leave the characteristics that do not apply.
POOL:
  [0] Connectionless: no session setup before data is sent
  [1] No acknowledgments or retransmission of lost segments
  [2] Fixed 8-byte header
  [3] Three-way handshake before the first data segment
  [4] Sequence numbers used to reorder and recover segments
  [5] Sliding-window flow control
  [6] Low overhead suited to delay-sensitive voice
KEY (unordered subset): [0] + [1] + [2] + [6]
why: UDP sends datagrams with no handshake, no acknowledgments, no retransmission and no windowing, using an 8-byte header (ports, length, checksum). That low overhead suits voice: a late packet is useless, so resending it would only add delay. The handshake, sequencing for recovery and sliding windows belong to TCP.
TAKEAWAY: TCP: connection-oriented, reliable, ordered, flow-controlled, 20-byte minimum header. UDP: connectionless, best effort, 8-byte header; used by voice/video, DNS queries, DHCP, TFTP, SNMP, syslog.

[a036] type=order domain=2 obj=2.5.a (Interpret basic operations of Rapid PVST+ Spanning Tree Protocol — Root port, root bridge (primary/secondary), and other port names)
Q: Drag the steps into the order Rapid PVST+ follows to build a loop-free topology for VLAN 10 across the campus switches.
POOL:
  [0] Each non-root switch selects one root port: its lowest-cost path to the root
  [1] All switches elect the root bridge: the lowest bridge ID
  [2] On each link, the port with the best path to the root becomes the designated port
  [3] Every remaining port becomes an alternate or backup port and discards

[a060] type=mc domain=4 obj=4.7 (Explain the forwarding per-hop behavior (PHB) for QoS such as classification, marking, queuing, congestion, policing, and shaping)
Q: EDGE-1's 1-Gb/s link to ISP-A is contracted at a 300-Mb/s CIR, and ISP-A drops everything above that rate. Off-site backup jobs burst far above 300 Mb/s and the resulting drops cause gaps in voice calls. Which QoS tool should EDGE-1 apply outbound on Gi0/1 to stay within the CIR while queuing excess bursts instead of dropping them?
  * A. Shaping
        why: A shaper buffers traffic that exceeds the configured rate and releases it at the CIR. It smooths bursts so the provider's policer never sees excess traffic.
    B. Policing
        why: A policer drops or re-marks traffic that exceeds the rate with no buffering. That is what ISP-A already does, and it is what causes the drops.
    C. Classification and marking
        why: Classification and marking identify traffic and set DSCP values. They do not limit the sending rate, so bursts would still exceed the CIR.
    D. Weighted random early detection (WRED)
        why: WRED drops packets early as a queue fills, to make TCP senders slow down. It does not hold traffic to a configured rate.
TAKEAWAY: Shaping buffers excess traffic (adds delay, avoids drops) and is applied outbound toward a slower contract. Policing drops or re-marks excess traffic and is typical at the provider's ingress.

  * A. It load-shares between next hops 10.40.250.2 and 10.40.250.3, because both paths have the same cost of 2

        why: Those are the router IDs of the routers that advertised the route (from ...). The next hops are their interface addresses, 10.40.250.2 and 10.40.250.3.
TAKEAWAY: show ip route <prefix>: distance = AD, metric = cost, one descriptor block per installed next hop, 'from' = the advertising router ID. Equal metrics = equal-cost load sharing (OSPF installs 4 by default).

[a088] type=mc domain=4 obj=4.4 (Explain the function of SNMP in network operations)
Q: The NOC wants CORE-1 to notify the network management station as soon as an interface goes down, and CORE-1 must send the notification again if the station does not acknowledge it. Which SNMP message type meets the requirement?
  * A. Inform
        why: An inform is an unsolicited notification from the agent that the manager must acknowledge. If no acknowledgment arrives, the agent resends it. Informs need SNMPv2c or SNMPv3.
    B. Trap
        why: A trap is also unsolicited, but it is fire-and-forget. If it is lost on the way to the NMS, the agent never knows and never resends it.
    C. Get-response
        why: This is the agent's reply to a Get request from the manager. The manager would have to poll; it is not an alert sent when the event happens.
    D. Set
        why: A Set is sent by the manager to change a value in the agent's MIB, such as shutting an interface. It flows the wrong way for an alert.
TAKEAWAY: SNMP: manager sends Get/GetNext/GetBulk/Set to the agent (UDP 161). The agent sends Trap (no ack) or Inform (acknowledged) to the manager (UDP 162). SNMPv3 adds authentication and encryption.

[a089] type=ms pick=2 domain=5 obj=5.7 (Configure and verify Layer 2 security features (DHCP snooping, dynamic ARP inspection, and port security))
Q: A student plugged a home router into a classroom jack on ACC-2, and PCs in VLAN 20 began receiving 192.168.0.x addresses. The real DHCP server is reached through the uplink to DIST-1. Which two configurations on ACC-2 block the rogue server while legitimate DHCP keeps working? (Choose two.)
  * A. ip dhcp snooping and ip dhcp snooping vlan 20 in global configuration
        why: This turns on DHCP snooping for VLAN 20. Every port becomes untrusted, and server messages such as DHCPOFFER and DHCPACK arriving on an untrusted port are dropped.
  * B. ip dhcp snooping trust on the uplink toward DIST-1
        why: The legitimate offers arrive on the uplink. Trusting only that port lets them through, while offers from the student's router on an access port are dropped.
    C. ip dhcp snooping trust on the classroom access ports
        why: That is backwards. Trusting the access ports would let the rogue router's offers through again.
    D. ip arp inspection vlan 20 in global configuration
        why: Dynamic ARP inspection checks ARP messages against the snooping bindings. It does not filter DHCP offers, so the rogue leases would continue.
    E. switchport port-security maximum 1 on the classroom access ports
        why: The home router uses one MAC address on the port, so port security would allow it. Port security limits MAC addresses; it does not look at DHCP messages.
TAKEAWAY: DHCP snooping: enable it globally and per VLAN, trust only the ports toward real DHCP servers (uplinks), leave access ports untrusted. Its binding table is what DAI and IP Source Guard rely on.

[a090] type=ms pick=3 domain=3 obj=3.4.a (Configure and verify single area OSPFv2 — Neighbor adjacencies)
Q: A new router, RES-1, will join the transit segment 10.40.250.0/24 where EDGE-1, DIST-1, DIST-2 and CORE-1 already run OSPF. Which three settings on RES-1's Gi0/0 must agree with the existing routers for adjacencies to form? (Choose three.)
  * A. Area ID (area 0)
        why: The area ID is carried in every hello. A router in another area on the same segment is ignored.
  * B. Subnet mask (/24)
        why: On broadcast segments the hello includes the interface mask, and neighbors must agree on it as well as on the subnet.
  * C. Hello and dead intervals
        why: Both timers are carried in the hello and must match exactly (10 and 40 seconds by default on Ethernet).
    D. OSPF process ID
        why: The process ID is local to each router and is not sent in any OSPF packet. router ospf 7 can peer with router ospf 1.
    E. Router priority
        why: Priority only affects the DR/BDR election. Routers with different priorities still form adjacencies.
    F. Router ID
        why: Router IDs must be unique, not equal. A duplicate router ID causes problems instead of preventing them.
TAKEAWAY: Must match: area, subnet/mask, hello/dead timers, authentication, stub flag (and MTU, checked at EXSTART). Must differ: router ID. Doesn't matter: process ID, priority, cost.

[a091] type=mc domain=3 obj=3.3.c (Configure and verify IPv4 and IPv6 static routing — Host route)
Q: Traffic from EDGE-1 to the NOC monitoring server 10.40.50.30 must pass through DIST-1 (10.40.250.2), where a traffic tap is installed. The rest of 10.40.50.0/24 must keep following the OSPF route through CORE-1. Which command on EDGE-1 meets the requirement?

[a096] type=mc domain=3 obj=3.5 (Describe the purpose, functions, and concepts of first hop redundancy protocols)
Q: The campus team wants both DIST-1 and DIST-2 to forward traffic from VLAN 40 hosts at the same time, while every host keeps the same default gateway address. Which first hop redundancy protocol does this within a single group?
  * A. GLBP
        why: In GLBP, the active virtual gateway (AVG) answers ARP requests for the one virtual IP with different virtual MACs, each owned by a forwarder (AVF). Hosts are spread across both switches automatically.
    B. HSRP
        why: One HSRP group has one active router that forwards for all hosts. Sharing load needs several groups and hosts split between different gateway addresses.
    C. VRRP
        why: Like HSRP, a VRRP group has one master that forwards. VRRP is the open-standard choice, but it does not load balance within a group.
    D. HSRP version 2
        why: Version 2 adds more group numbers, millisecond timers and IPv6. It still has only one active router per group.
TAKEAWAY: HSRP (Cisco): active/standby, preempt off. VRRP (open): master/backup, preempt on. GLBP (Cisco): one virtual IP, several virtual MACs, AVG + AVFs share the load.

[a100] type=mc domain=5 obj=5.8 (Compare authentication, authorization, and accounting concepts)
Q: After an outage, the NOC needs to know which administrator entered which configuration commands on CORE-1 and at what time. Which AAA function provides this record?
  * A. Accounting
        why: Accounting records what authenticated users did: sessions, commands and times. With TACACS+, each command can be logged to the server.
    B. Authentication
        why: Authentication proves who the user is at login. It does not record what they did afterwards.
    C. Authorization
        why: Authorization decides which commands a user may run. It allows or denies; it does not keep a history.

        why: Auditing is a broader review activity, not one of the three AAA functions. The AAA function that produces the record is accounting.
