[s001] type=mc domain=3 obj=3.1.1 (Describe Azure DDoS Protection)
Q: Fabrikam hosts a single public-facing web application in Azure that uses one public IP address. The company wants DDoS mitigation tuned to its traffic, with attack telemetry, but does not want to purchase a protection plan that covers entire virtual networks. Which Azure service tier should Fabrikam use?
  * A. Azure DDoS IP Protection
        why: IP Protection is billed per protected public IP and needs no plan, while still giving adaptive tuning, metrics and alerting.
    B. Azure DDoS Network Protection
        why: Network Protection is purchased as a plan that covers all protected resources in enrolled virtual networks, which is more than Fabrikam wants.
    C. Azure DDoS infrastructure protection
        why: The free baseline is always on but offers no customer-specific tuning, telemetry or alerting.
    D. Azure Web Application Firewall
        why: WAF protects against HTTP-layer attacks such as injection; it is not a volumetric DDoS mitigation service.
TAKEAWAY: DDoS Network Protection is a per-VNet plan; DDoS IP Protection is per public IP with no plan. Both mitigate L3/L4 floods; WAF handles L7.

[s002] type=mc domain=2 obj=2.1.2 (Describe types of identities, including workload identities)
Q: An Azure virtual machine at Northwind runs an application that must read a connection string from Azure Key Vault. The security team requires that no credential be stored in the application's configuration and that Azure rotates the identity's credentials automatically. Which type of identity should the application use?
  * A. A managed identity
        why: A managed identity is a service principal whose credentials Azure creates and rotates; the VM authenticates to Key Vault without storing anything.
    B. A user account with a long password
        why: A user account is a human identity and would require a stored password, violating the requirement.
    C. A guest user from a partner tenant
        why: B2B guests are external human identities for collaboration, not workload identities for an Azure resource.
    D. A device identity for the virtual machine
        why: A device identity supports device-based Conditional Access; it does not give an application a way to call Key Vault.
TAKEAWAY: Workload identities in Entra: applications, service principals and managed identities. 'No stored credentials' plus 'Azure resource' points to a managed identity.

[s004] type=mc domain=3 obj=3.1.5 (Describe network security groups (NSGs))
Q: You review the inbound security rules of a network security group associated with a subnet at Woodgrove Bank, shown in the exhibit. A user on the internet at 203.0.113.25 attempts an RDP connection to a VM in the subnet. What happens to the connection?
EXHIBIT:
    Priority  Name              Source           Dest  Port   Protocol  Action
    100       Deny-RDP-Internet Internet         Any   3389   TCP       Deny
    200       Allow-RDP-Mgmt    10.10.5.0/24     Any   3389   TCP       Allow
    300       Allow-HTTPS       Any              Any   443    TCP       Allow
    65000     AllowVNetInBound  VirtualNetwork   VNet  Any    Any       Allow
    65001     AllowAzureLBIn    AzureLoadBalancer Any  Any    Any       Allow
    65500     DenyAllInbound    Any              Any   Any    Any       Deny
  * A. It is denied by the rule at priority 100
        why: Rules are evaluated lowest priority number first and processing stops at the first match. Internet-sourced RDP matches priority 100, which denies it.
    B. It is allowed by the rule at priority 200
        why: Priority 200 is never reached for this packet because priority 100 already matched, and the source is not 10.10.5.0/24 anyway.
    C. It is allowed by the default AllowVNetInBound rule
        why: The source is the internet, not the VirtualNetwork service tag, and default rules are only reached if no custom rule matches.
    D. It is denied by the default DenyAllInbound rule
        why: The packet never falls through to 65500 because a custom rule at priority 100 matched it first.
TAKEAWAY: NSG evaluation: ascending priority, first match wins, custom rules 100–4096 run before defaults at 65000+.

[s014] type=mc domain=4 obj=4.3.6 (Describe retention policies, retention labels, and retention label policies)
Q: A document in a Litware SharePoint site is subject to the two retention settings shown in the exhibit. Based on the principles of retention, what happens to the document?
EXHIBIT:
    Setting                         Type              Action                      Period
    All-Sites-Baseline              Retention policy  Retain, then delete         7 years
    Contracts (applied by user)     Retention label   Delete only                 3 years
  * A. It is retained for 7 years and then deleted
        why: Retention wins over deletion, so the label's 3-year delete cannot remove the item while the policy retains it; the item is kept the full 7 years and then deleted.
    B. It is deleted after 3 years because the label is explicit
        why: Explicit-over-implicit only decides among competing settings of the same kind; retention always beats deletion first.
    C. It is retained for 10 years, the sum of both periods

    D. It is deleted after 3 years and the policy no longer applies
        why: The retention policy continues to apply to the site and keeps the item in place.
TAKEAWAY: Principles of retention: 1) retention wins over deletion, 2) longest retention wins, 3) explicit wins over implicit, 4) shortest deletion wins. Stop at the first rule that decides.

[s021] type=mc domain=1 obj=1.1.4 (Describe encryption and hashing)
Q: A Fabrikam developer stores user passwords by running each one through SHA-256 and keeping only the output. A reviewer notes that two users with the same password have identical stored values and that precomputed tables could reveal common passwords. Which change addresses the reviewer's concern?
  * A. Add a unique random salt to each password before hashing
        why: Salting makes identical passwords produce different hashes and renders precomputed rainbow tables useless.
    B. Encrypt the passwords with a symmetric key instead of hashing them
        why: Reversible encryption is weaker for password storage because anyone with the key can recover every password.
    C. Hash the passwords twice with the same algorithm
        why: Double hashing is still deterministic; identical passwords remain identical and tables can be precomputed.
    D. Store the passwords with asymmetric encryption using the public key
        why: Passwords should not be recoverable at all; hashing with a salt, not encryption, is the correct design.
TAKEAWAY: Hashing is one-way and deterministic; a per-user salt defeats rainbow tables. Encryption is reversible and is for confidentiality, not password storage.
