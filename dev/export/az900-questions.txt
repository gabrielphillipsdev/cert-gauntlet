[z001] type=mc domain=1 obj=1.1.2 (Describe the shared responsibility model)
Q: Fabrikam runs a line-of-business application on an Azure virtual machine that runs Windows Server. A critical operating system security update is released. According to the shared responsibility model, who is responsible for installing the update?
  * A. Fabrikam
        why: A virtual machine is IaaS. The customer owns everything from the guest operating system upward, including OS patching.
    B. Microsoft
        why: Microsoft patches the physical hosts and the hypervisor, not the guest operating system inside a customer's VM.
    C. Fabrikam and Microsoft share the task equally
        why: Guest OS maintenance is not a shared item in IaaS; it belongs entirely to the customer.
    D. The software vendor of the line-of-business application
        why: An application vendor supports its own product and has no role in the operating system beneath it.
TAKEAWAY: IaaS: customer owns the guest OS and everything above it. The provider owns the physical datacenter, network and hosts in every model.

[z002] type=mc domain=2 obj=2.1.2 (Describe availability zones)
Q: Northwind plans to deploy a web application to Azure. The application must remain available if a single datacenter in the region fails, and all data must stay within one region. Which Azure feature should Northwind use?
  * A. Availability zones
        why: Zones are physically separate datacenter groups within one region, so deploying across zones survives a datacenter failure while keeping data in the region.
    B. Region pairs
        why: A region pair involves a second region, which would move data outside the single region the requirement specifies.
    C. Resource groups
        why: A resource group is a logical container for management; it provides no physical redundancy.
    D. Management groups
        why: Management groups organize subscriptions for governance and have nothing to do with datacenter resilience.
TAKEAWAY: Datacenter failure inside a region = availability zones. Whole-region failure = a second region (often the paired region).

[z003] type=mc domain=3 obj=3.1.4 (Describe the purpose of tags)
Q: Tailspin applies the tags shown in the exhibit. A user then creates a new virtual machine named VM3 in RG-Finance without specifying any tags. Which tags does VM3 have?
EXHIBIT:
    Scope                     Tag
    ------------------------  --------------------
    Subscription Sub-Prod     Owner=CloudOps
    Resource group RG-Finance Dept=Finance
    VM1 (in RG-Finance)       Env=Prod
    VM2 (in RG-Finance)       Env=Test
  * A. No tags
        why: Tags are not inherited from the resource group or subscription. A resource carries only the tags set directly on it, so VM3 starts with none.
    B. Dept=Finance only
        why: The resource group's tag does not flow down to resources created inside it unless an Azure Policy copies it.
    C. Owner=CloudOps and Dept=Finance
        why: Neither subscription nor resource group tags are inherited by child resources by default.
    D. Owner=CloudOps, Dept=Finance and Env=Prod
        why: Tags on a sibling VM have no effect on a new VM, and parent-scope tags are not inherited.
TAKEAWAY: Use Azure Policy built-ins (Require a tag = Deny, Append a tag = Append, Inherit a tag from the resource group = Modify) to make child resources carry the parent's tag.

[z004] type=ms domain=1 obj=1.1.3 (Define cloud models, including public, private, and hybrid)

    C. Hardware is dedicated to a single organization

[z009] type=mc domain=3 obj=3.1.3 (Describe cost management capabilities in Azure)

[z012] type=mc domain=3 obj=3.2.3 (Describe the purpose of resource locks)

        why: A ReadOnly lock prevents modification regardless of RBAC. Even an Owner must remove the lock first.

        why: Locks are not overridden by role assignments; they apply to all users.

[z037] type=mc domain=2 obj=2.4.6 (Describe the concept of Zero Trust)
Q: Tailspin adopts a security model in which every access request is authenticated and authorized using all available signals, regardless of whether it originates from inside or outside the corporate network. Which Zero Trust principle does this describe?
  * A. Verify explicitly
        why: Verify explicitly means always authenticating and authorizing based on all available data points, never trusting network location.
    B. Use least privilege access
        why: Least privilege limits how much access is granted and for how long; it is not about verifying each request.
    C. Assume breach
        why: Assume breach drives segmentation, encryption and detection on the premise that attackers are already inside.

        why: Defense in depth is a layered-control model, not one of the three Zero Trust principles.
TAKEAWAY: Zero Trust principles: verify explicitly, use least privilege access, assume breach.
